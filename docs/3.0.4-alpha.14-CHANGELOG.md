# 3.0.4-alpha.14 — Retain the unlock bridge through a long lock-screen wait

Preserve alpha.13 as the only user-confirmed partly working rollback baseline; see KNOWN_WORKING_BUILD.md for its exact release, APK and source commit.

Remove the two-second end to keyguard observation. While a Home-return bridge is armed and the display is interactive, continue checking lock state across any length of lock-screen wait. Keep the selected photo prepared but hidden while locked. Sleep, shutdown, another active app or a completed handoff still removes it.

A Home attachment acknowledgement now submits a Home photo transaction and waits for its transaction-committed callback, followed by the next frame callback, before removing the temporary photo. This is stronger than submission acknowledgement, but is not proof of physical panel presentation. Epoch and entry checks prevent stale callbacks from removing a newer bridge. A separate two-second timeout, starting only after unlock is observed, remains a failure fallback; it is not the normal handoff timer.

Validation: Java compilation and 14 focused policy/lifecycle tests, including a 60-second lock wait without consuming the unlock timeout budget. CI runs release tests, lint, assembly and signing. Handset validation should cover immediate unlock, 5–10 seconds waiting while awake/locked, app-unlock, and sleep during handoff. Alpha.14 remains experimental until user confirmation.
