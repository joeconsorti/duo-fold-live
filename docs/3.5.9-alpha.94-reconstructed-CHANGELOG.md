# 3.5.9-alpha.94 reconstructed

Adds a bounded native endpoint check after Duo's animation layers and power handles are released. A healthy native device state, physical primary and selected app layout finish the check immediately without corrective writes.

A persistent mismatch is confirmed on a later tick at least 50 ms after the first observation. The check can release a residual request belonging to Duo's client, return the still-selected exclusive app root to the native primary, or ask WindowManager to update configuration and layout after a confirmed bounds or display-rotation mismatch. Each completed animation allows at most one correction. A follow-up read distinguishes submitted repairs from verified state/layout. The check expires after 500 ms and never gates the next animation.

Fresh endpoint input, physical base state, primary identity, foreground task, visibility and unlock checks guard corrections. New motion, disable, locking or stale input revokes pending work. Home follows Android's replacement launcher root. Workspace membership and bounds are inspected through the existing native path. Normal portrait/landscape selection follows the existing saved rotation policy.

The check does not establish optical correctness or detect arbitrary app-internal freezes. Foreign device-state requests, unresolved physical mappings and unavailable observations are reported without forcing a new display mode. Frame timing, visible flashes and real-device correction behavior require handset testing.

Validation covers healthy no-op completion in both directions, pending layer removal, one-shot correction and readback, stale input, changed foreground, changed physical posture during correction, expired checks, app placement, Home layout, task rotation and state-request ownership. Build with tools/build_local_test.py for unit tests, APK identity checks and matching source packaging.
