
## Automatic live B8 handoff

This corrects alpha.2's scope: Developer settings now enables the actual automatic hinge-driven B8 handoff inside Duo's live animation. The manual Lab entry is removed from this settings screen.

### Use

1. Install this signed GitHub pre-release as an update to Duo Fold Live.
2. Keep Shizuku connected and **Enable animation ON**.
3. In **Developer settings**, enable **Live B8 handoff (experimental)**. It is off by default. Enabling it selects Live Screen mode.
4. Open a fullscreen app and fold/unfold normally. No app picker, countdown, or test button is needed.

The existing handoff angle controls opening; closing uses the existing 4-degree hysteresis. The controller prewarms from live motion, moves the foreground exclusive fullscreen app, waits for destination geometry, commits the tested mirror/frozen-frame shield, applies the tested physical brightness hold, switches the primary designation, verifies physical identity and geometry, then reveals. Native endpoint release is also protected when Android has not already released the request.

The tested mirror and brightness implementation is preserved. Home, split-screen and Duo's control UI use protected native routing without explicitly moving unrelated tasks; those cases are not claimed equivalent to the tested fullscreen path. The existing glass renderer and customization remain in place. Competing legacy preview/handoff layers are suspended while B8 owns the route.

Disabling the mode, locking, losing the heartbeat or exceeding the 2-second angle grace requests cleanup. The normal controller remains suspended until owned power overrides release. Failed transitions are not automatically retried during the same mid-fold episode. Temporary mirrors retain their independent bounded watchdogs.

Status reports include the bounded live B8 transition trace. This is software evidence, not proof of visible pixels. The earlier occasional flash and historical mirror-related framework restart are not claimed fixed by this integration. This automatic integration still needs testing on the handset in both directions.

Validation includes the unchanged B8 engine fingerprint checks, deterministic tests of the actual live controller, Android compilation, unit tests, lint and signed APK verification. Main/stable and the standalone Lab checkpoint are unchanged.
