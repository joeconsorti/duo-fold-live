# 3.0.4-alpha.17 — Tighten unfold reveal readiness

Keep alpha.16 wallpaper behavior unchanged. Require a fresh post-ON content capture for both a committed inner glass frame and the fully-open clear-frame path. A clear surface alone is no longer readiness evidence. Invalidate pending frame callbacks on surface resize so an older-sized frame cannot qualify after reconfiguration.

Request a fresh capture when an animation surface is created/resized. For the next 900 ms, retry capture at a 16 ms minimum interval after completion instead of waiting up to 600 ms after an OFF/remap failure. Requests remain serial. Committed renderer notifications schedule a fade check after the existing 2 ms settle instead of waiting solely for the next fade VSYNC.

The existing 900 ms emergency recovery remains explicitly marked as unconfirmed; it prevents an indefinitely black display if capture fails. Fresh compositor capture plus committed animation is stronger evidence, but cannot guarantee another app has finished loading its own content. Device testing is required. Rotation, wallpaper and animation geometry are unchanged.

Validation: reveal-policy regression tests cover stale/pre-ON/missing captures, endpoint readiness, OFF interruption and explicit timeout recovery. Full Kotlin/Java compile, unit tests, lint, assembly and signing run in CI. Main/latest remains alpha.16; this build is a prerelease.
