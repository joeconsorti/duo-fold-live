# Alpha.60 reconstructed — mode integration and thermal review

Version code 1313. Based on committed alpha.59 (28f2486). Recovery target remains
alpha.20; no claim of original-source or handset equivalence. No GitHub push or
public release is performed by this local candidate build.

## Integration

FoldingModeSettings owns the public Live Screen / Screenshot selection. It reads
legacy selection before historical startup migrations, then normalizes route flags
before services start. Old `dual` and private B8 selections become the tested
coordinated Screenshot route; existing Live Screen stays Live. Both debug and
release pickers use this policy. The old Screenshot unlock and conflicting developer
route controls are removed. Retired renderer/controller code remains unreachable
from mode selection to avoid changing the tested shared handoff implementation.

Screenshot always enables the same coordinated Windowed Glass setting used in
the accepted alpha.59 report. GlassFrames' continuous capture suppression is now
specific to Screenshot. LiveVeil's plain-baseline override is restricted to the
retired legacy route, restoring Live Screen's shader and its existing pause easing.
Stopping all features still disables animation and stops helpers, but retains the
mode selection for the next enable. Capture timing, app transfers, thermal threshold,
frame cap, and the shared 1250 ms / 90° / 5° gesture are unchanged.

The existing signed GitHub workflow is the intended public distribution path:
`org.duofold.live`, signed by the repository's existing signing secret. The private
debug APK is `org.duofold.live.test`, not an in-place update for the public package.
CI's version allowlist now accepts the required `-reconstructed` suffix. The current
workflow publishes on branch pushes, so no candidate branch should be pushed until
the thermal condition is resolved. Do not substitute a new release signing key.

## Supplied alpha.59 thermal evidence

Only the 13 current-build Fold health entries are counted. They span 73.784 s,
with 32.266 s of presentation time and 10.666 s of app CPU: a duration-weighted
33.06% of one core during presentations (individual sessions 26.81–46.04%).
This excludes shell helpers, compositor, GPU and idle intervals. It does not
measure total device load or attribute heating to Duo.

Battery readings rose from 31.9°C to 33.1°C. Five sessions peaked at thermal 0,
six at 1, and two at 2; the latest start gate also reports 2. Android defines 2
as moderate throttling, 3 as severe. No current-build severe sample is shown.
Battery temperature alone cannot clear device thermal status.
Reference: https://developer.android.com/reference/android/os/PowerManager

The report has only one alpha.59 long-interval health row, at process startup.
Older alpha.56/58 idle rows do not validate alpha.59 idle behavior or memory trends.
Crash-buffer exceptions belong to other apps; the previous-session presentation
lease abort predates alpha.59. Neither is a current-build Duo crash finding.

Repeated PAUSE_SETTLED and final CLEANUP_COMPLETE show software cleanup, not
physical power/GPU idleness. The Home endpoint removal was submitted in 2 ms;
that is not optical timing. A clean thermal pass needs follow-up from a cooled
status-0 baseline through ordinary folding and an idle period, to check recovery
and whether status 2 recurs. No handset is connected to this build environment.

## Validation scope

Migration tests cover fresh installs, both legacy routes, private plain/glass
selection, startup ordering, round-trip mode switching, stale flags, retained
appearance, disabled animation and Live preview preference. Existing gesture tests
exercise both modes, both directions, exact 90°, jitter and exact 5° resumption.
Production controller replays cover Screenshot pause, return, resume and cleanup.
These checks and APK compilation do not establish handset/optical behavior.

## Release-check repairs

Release lint found pre-existing raw API constants and missing API-level annotations
from the private build series. Constants now use their same-valued Android names.
The independent buffer/scene classes document their existing Android 15+ route
gate with TargetApi(35); no runtime gate, capture, frame pacing or animation
behavior changes. The scene replay has a compile-only annotation stub. The root
privacy document is synchronized with the already updated bundled policy covering
isolated Home captures and opt-in image diagnostics; both refer to Screenshot Mode.
