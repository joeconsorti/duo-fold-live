
## Live B8 lifecycle and diagnostic fixes

Alpha.3's report showed destination wallpaper being shielded, approximately 2.5-second shield lifetimes, and a second endpoint shield aborting while reading brightness logs. A phone/framework restart and excessive warmth were reported; this report did not establish the crash cause or prove a buffer leak.

- Select and move an exclusive fullscreen task before destination shielding. Duo's own fullscreen activity is now eligible. Remove the silent native-only fallback: Home/split-screen or ambiguous focus is logged and the experimental transfer is aborted, without freezing wallpaper as though it were the selected app.
- Prepare and validate brightness before creating a shield. No logcat read runs behind a submitted shield. Endpoint reuse extends the existing bounded brightness writer rather than starting a competing writer.
- When the endpoint is reached during promotion, reuse the active shield for native release. A later endpoint can still require a separate protected release; it uses prepared brightness, not another blocking log read.
- Retain the 300 ms geometry-stability check; shorten the following reveal delay from 750 to 150 ms. Remove immediately after the hide commit instead of another 250 ms delay.
- Explicitly detach frozen buffers and wait for the removal transaction callback before releasing handles and allowing another shield. Report counts, estimated RGBA bytes, shield age and removal confirmation. These are not actual GPU allocation measurements or optical proof.
- Reduce B8 angle polling from the 4 ms target to 16 ms in motion and 32 ms at endpoints. Severe thermal status pauses B8 and its effect. Normal-mode cadence is unchanged.
- Persist a bounded transition journal with boot identity, helper PID, thread/file-descriptor counts and Java heap usage. Include previous-session evidence and a bounded crash-buffer excerpt in the copied status report. No screenshot files or automatic uploads are added.

The mirror method remains in use. The original Lab engine files remain unchanged as a checkpoint; live-specific bridge/brightness variants contain the lifecycle adaptations. The standalone diagnostic app and main/stable are untouched.

### Test only after cooling

Install as an update, leave Enable animation ON, then enable Developer settings → Live B8 handoff (experimental). Start with one fullscreen app and one fold/unfold cycle. Copy status report immediately, with the app name, direction and what you saw. If it reboots or becomes unusually hot again, stop testing; the build adds evidence, not a proven fix for the historical system crash.

Validation: controller lifecycle tests, real bridge cleanup and cached-brightness tests using a fake Android platform, preserved-engine checks, Android compilation, unit tests, lint and signed APK verification. Handset behavior remains unverified until tested.
