# Duo Fold Live 3.5.3-alpha.13

Based on alpha.12. Main remains 3.5.2.

- Four-finger tap on an app activity screen opens Advanced / Developer settings and scrolls to the existing entry. The shortcut also returns to the main settings page from other Duo activities. Requires a stationary tap within 500 ms; five-finger, drag, and canceled gestures do not activate. Other applications and system windows are not monitored.
- Adds opt-in **Hold displays ON at handoff (experimental)**, default OFF. Requires dual screenshot handoff and window-first startup. Near 150 degrees opening or 30 degrees closing, request Samsung state-ON overrides for D0/D1 once per session. Release owned tokens after two seconds, on disable/stop or unrelated loss of usability. A verified reason-13 fold sleep retains only the existing bounded lease; it does not extend it. Rejection and cleanup results are logged independently.
- Endpoint sampling now runs on a separate worker for 3.5 seconds and records maximum sample gap. This avoids waiting behind the task-transfer transaction, though Binder/display locks may still delay observations.
- Keeps alpha.12 endpoint ordering and both report buttons.

Validation: full CI unit tests, lint, build, signature/alignment checks. Gesture and Samsung power behavior need phone validation. An accepted override is not proof of optical continuity; the remapper may still insist on OFF or delay until the override clears. Rotation restoration readback mismatch remains under investigation.

## Samsung call-site evidence

Public decompiled One UI 8 reference, commit d7c13fe69a1ad46f8dff0254f1abd32596fef5cd, not the user's exact Android 17 service implementation:

- packages/SystemUI/src/com/android/systemui/doze/PluginAODManager.java calls setDisplayStateOverrideWithDisplayId(token, state, displayId, 10000).
- packages/SystemUI/src/com/android/systemui/power/DozeChargingHelper.java requests setDisplayStateOverride(token, 2, 4500) and releases with (token, 0, -1).
- Older Samsung DisplayManagerService implementation associates requests with Binder tokens, removes state-0 requests, and links token death for cleanup.

Experiment uses the observed four-argument shape, its 10000 trailing value, and state-0/-1 release convention. The exact Android 17 interpretation/precedence of the trailing argument is not established; a separate two-second client release is implemented rather than relying on its meaning.

Reference: https://github.com/488315/android_samsung_frameworks_base/tree/d7c13fe69a1ad46f8dff0254f1abd32596fef5cd
