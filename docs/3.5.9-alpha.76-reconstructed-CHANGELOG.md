# Alpha.76 reconstructed local — rollback of the last two builds

VersionCode 1329. Runtime and unit-test source restored byte-for-byte to alpha.73
commit ac0e3abb2202063518e92f83438bb47b8c107680. Based on the preserved alpha.75
history, not a history reset. Recovery target remains alpha.20. This is a
reconstructed regression-test build, not a verified screen-power fix.

## Reason and evidence

The user confirms that the screen itself shuts off during the animation and says
this was absent in several earlier builds, returning in the last two or three.
An exact last-good version was not supplied. Alpha.73 is the comparison baseline
immediately preceding the last two releases; it is not asserted to be optically
verified as the last-good power baseline.

The latest alpha.75 closing app trace requests the new primary at 424412792.
Both logical displays report OFF at 424412867, then D0 reports ON at 424412907
and D1 at 424412916. These callback intervals are 40 and 49 ms. Physical panels
exchange logical IDs during the transition, and callback intervals are not exact
optical blackout durations. The user's direct observation establishes the
visible complaint; no additional proof is required to accept it.

The token-owned both-ON implementation in LiveB8Power did not change in alpha.74
or alpha.75. Alpha.75 removed Home's optional physical brightness hold and added
stricter scene mapping, display-event registration, buffer-command reuse and
deferred hidden-host updates. The supplied firmware rejects the new listener
signature with NoSuchMethodException, leaving polling active. Alpha.74 changed
pose smoothing, rotation restoration, wake-preparation triggering and an image
agreement threshold. No individual change is proven responsible. App brightness
protection was not removed, so restoring Home's hold alone cannot be claimed to
explain or fix the ordinary-app OFF/ON observations.

## Rollback scope

Restore all runtime source and unit tests changed by alpha.74 and alpha.75 to
alpha.73. This includes Home's passive optional brightness preparation and hold,
the original mapping checks, per-frame buffer configuration, primary-host update
timing, pose smoothing, rotation restoration and wake-preparation trigger. It
also restores the older diagnostic gap calculation; do not compare its reported
maxMovingGapMs directly with alpha.75's corrected metric.

The alpha.73 composed-Home wallpaper correction, app capture ownership guards,
independent moving layers and bounded Home endpoint power tail are retained.
There is no new global power override, raw physical power-mode command, wake loop,
persistent setting or forced brightness value. The package/signing identity stays
compatible with installed local builds, and the higher version code allows a
normal update without uninstalling. Existing per-build migration still resets
Advanced animation controls; settings outside that group and app data remain.
Only the new version metadata and this release note differ from the baseline
runtime/build configuration.

Tests and platform fakes return to the same baseline too. The buffer harness
retains its alpha.75 compile correction supplying the existing fourth rootCrop
callback; that correction does not alter runtime behavior. Later changelogs and
all Git history remain available in the delivered source archive.

## Verification and next handset check

Before building, verify zero differences in app/src against the baseline commit
and verify build configuration differs only in versionCode/versionName. Run the
controller, scene, brightness, task, power and cleanup harnesses, then the clean
delivery build's complete JVM suite, lint and compiled rendering/capture harnesses.
Verify APK package/version/signature, source archive and manifest hashes. Save
the APK and complete source/history archive durably before handing them over.

On the phone, check Advanced animation controls after updating and restore any
custom values before comparing the same Home and X opening/closing motions.
Check that both screens stay lit through the motion and the destination
remains lit at completion. This rollback is the implementation change under test;
host tests cannot establish optical success. If shutoff remains, alpha.73 is not
an adequate power baseline, and the regression search must include alpha.72 and
earlier or changes in firmware/settings. Do not declare the issue unavoidable
from AOSP behavior or add unrelated rendering tweaks as a claimed power fix.

Overhead optimizations from the last two builds are deliberately backed out with
their behavior changes. No CPU, battery or smoothness improvement is claimed.
Reintroduce those changes individually only after panel continuity is confirmed.
