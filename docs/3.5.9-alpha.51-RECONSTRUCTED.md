## Changes

- Native readiness checks retry after 50ms instead of 150ms after a success.
  The two distinct successful observations spanning at least 100ms, 75ms geometry
  stability, post-release freshness, task identity and physical mapping gates remain.
  Readiness has its own app executor and no longer waits behind fold-setting
  operations or an entire physical diagnostic capture in the shell Binder monitor.
  Capture API initialization and settings writes retain separate synchronization;
  per-request buffers, listeners and exclusion references remain local.
- Once native endpoint readiness succeeds, independent scene roots are revoked
  from all layer stacks before power/brightness resource cleanup. Route ownership
  remains held until removal acknowledgement and all cleanup complete. Black guard
  layers are explicitly hidden and detached from every stack in the same removal
  transaction before becoming parentless, closing a teardown exposure risk. Late app
  submissions cannot restore a root's detached layer stack. Unverified fallback,
  abort and intermediate handoff continue retaining coverage during restoration.
  ENDPOINT_OBSERVED and NATIVE_REVEAL_SUBMITTED report the software interval.
- A separate Home path accepts only the actual focused fullscreen HOME task of
  the same launcher/user. It never moves or focuses Home roots. Both physical
  renderers initially project the captured Home composition. Android owns launcher
  placement at primary remap; fresh layout checks identify its actual primary Home
  task, then capture it under the moving coverage. Custom wallpaper is included
  for Home; normal app capture exclusions are unchanged. A matching committed
  native Home image plus fresh window readiness is required before completion.
  Task replacement invalidates old capture/readiness replies. Returning to an
  unchanged Home endpoint reuses its already captured native image. Home requires
  the Android 15+ independent route; legacy standard-app routing is unchanged.
- Physical diagnostics use DisplayCaptureArgs.Builder.setSize, whose documented
  role is sizing the returned buffer, instead of the layer-capture frame scale.
  HardwareBuffer dimensions must be <=320 before CPU readback. OEMs ignoring the
  requested size produce an inconclusive error rather than transferring and PNG
  encoding full-resolution frames. A busy window observation is labeled unavailable
  without discarding an otherwise captured image. Retention is 24 sample folders,
  sufficient for the six-fold/four-samples-per-fold budget. Duplicate revisions
  no longer consume another slot for the same physical panel and stage.
- A rejected GPU draw no longer latches an animated startup as if submitted.
  Accepted draws still latch immediately, preserving alpha50's protection against
  a late callback replacing an already visible animation with a plain frame.
