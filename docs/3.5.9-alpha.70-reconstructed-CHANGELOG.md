## App and animation first

Optional bar requests and new cosmetic compositions yield during source/app
capture, primary readiness, remapping, endpoint release and hinge-pause return.
Discovery starts after native app readiness and known physical-panel geometry.
It never participates in the app-readiness frame or handoff acknowledgement.
An already-published texture remains in use while optional work is suspended.

Critical helper calls invalidate in-flight optional work. Bar metadata uses a
separate single-flight dump lane with a 150 ms reader budget, so an outstanding
bar dump cannot reserve the app-readiness lane or cause that lane's busy error.
An Android Binder call already running cannot be preempted: it may finish, but
its obsolete bar result is discarded. No queue or busy-wait is added to the
readiness path. The operating system can still impose its own service delays.

Destination-only discovery has at most five requests, at least 300 ms apart,
within a 1500 ms wall-clock opportunity. It stops as soon as status plus inner
taskbar (or cover navigation) are captured. Partial status can appear while the
taskbar is still missing. Slow, superseded and post-close results are discarded;
missing bars do not extend the animation. Each geometry revision needs one
pixel capture; unchanged revisions use metadata only while discovery remains
eligible. Other comparison modes retain their separate refresh policies.

The physical scene supplies expected width, height, rotation and output raster.
Both helper and delivery checks require those known dimensions, as well as
physical ID, current mapping, ON state and unlocked state. Transitional inner
geometry cannot be accepted for the cover simply because its ID changed first.

## Less optional image work

Destination pixels remain part of the base animation input, with the existing
projection, motion, glass and blur effects. Both optional capture and composition
are capped to the session's actual output extent, with the existing 1440-pixel
ceiling and no upsampling of the original capture. At the logged 25% settings,
the longest extents are 493 pixels for cover and 612 for inner instead of 1440.
These are configured limits, not measured handset performance improvements.

Existing guarded images are borrowed with source rectangles: accepting an app
frame no longer crops/copies destination-bar bitmaps on the main callback. A
low-priority worker builds the cosmetic texture and blur pyramid once, then
animation frames reuse it. Optional allocation failure preserves the base
image. Late/unpublished composites are recycled; published or borrowed images
are not recycled while a renderer may still reference them.

## Brief angle gaps retain coverage

An existing direct scene with an app image may keep its last frame between
750 and 1999 ms angle age. It does not advance motion, start capture/composition,
acknowledge readiness or start a new scene from that stale sample. Fresh input
resumes the same scene. At 2000 ms it expires in line with the shell limit.
The direct-frame heartbeat lease is also bounded to 2000 ms. Lock, power,
settings, thermal and overall session expiry checks still apply immediately.
