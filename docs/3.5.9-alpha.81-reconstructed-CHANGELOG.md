# Alpha.81 reconstructed — Home brightness preparation and cleanup

Based on alpha.80 source commit `c755bb2f5c0fa5b44bd483c241b64fed4e611d6d`.
Test package `org.duofold.live.test`, version code 1334,
`3.5.9-alpha.81-reconstructed-local`. This build repairs brightness lifecycle
gaps. It is not a certified blackout-free public release.

## Evidence from the alpha.80 handset report

The user observed a large fade to black and back after the first opening, then
a brief black flash while closing. There is no video or composition image
sequence in this report, so their exact optical timing is unmeasured.

| Event | Current-build software evidence |
| --- | --- |
| First opening, session 513801992 | Brightness preparation failed at 513802402 because the cover physical sample was unavailable. `HOME_BRIGHTNESS_NATIVE` at 513802974 explicitly proceeded without the optional B8 brightness hold. |
| Opening native Home | The remap starts near 20 degrees. Both display OFF callbacks occur around 513803083; ON callbacks follow. Draw-state and faded-Home capture guards reject destination images until the valid capture stamped 513803873. These checks correctly keep rejected images out of the animation. |
| Closing, session 513806217 | Brightness preparation succeeds, and `HOME_BRIGHTNESS_HOLD` precedes the primary request at 513806737. Both panels are nevertheless sampled OFF at 513806799 and ON at 513806841. This is a separate remaining power-transition concern; the sample span is not an optical blackout duration. |
| Final cover animation | Both renderers report committed angle 0 at raw angle 0. Cover native texture submission begins at 513807468, before the 513808561 endpoint. The endpoint pose-lag defect addressed by alpha.80 does not recur in this report. |
| Closing resource release | Images are removed immediately at the endpoint. Alpha.80 also stops brightness before its existing power tail waits for native cancellation and cover stability. That leaves the tail without brightness protection. The report does not establish that this caused the user's brief closing flash. |

Old ChatGPT/camera crash entries and process-wide idle OFF counters are not
evidence of a current Duo crash or the number of visible flashes.

## Changes

1. Home once again prepares missing physical brightness samples using the
   original B8 refresh mechanism. It runs alongside capture/render preparation.
   Each initial log observation is limited to 400 ms. A missing panel may receive
   one temporary brightness step of 1/255; the override is cleared, and only a
   positive, fresh physical command observed after clearing can authorize a hold.
   Saved brightness settings are unchanged; the existing detached cleanup
   watchdog remains in force. Probe values, stale values and guessed brightness
   remain rejected.
2. If preparation is still pending when Home is ready to remap, the moving
   presentation continues for at most 600 ms of additional preparation time.
   Failure or timeout does not abort native Home preparation or take the ordinary
   app route's multi-second fallback. On timeout, preparation is closed before
   the primary request. Full-open/full-close endpoint bypass, lock, disable and
   stale-input cleanup take precedence and cancel preparation immediately.
3. At full close, an already-running brightness writer may narrow to the cover
   physical ID during the existing maximum 400 ms power tail. It stops writing
   the inner panel. It cannot create a writer from prepared samples, revive an
   expired/stopped writer, change panel power mode, renew ON leases, or hold an
   image over Home. Native cover stability, timeout, reversal, lock and disable
   all stop it. The original maximum four-second writer lifetime still applies.
4. Cleanup serializes with in-flight physical brightness writes. It also
   synchronizes with refresh ownership creation, so a late preparation worker
   cannot acquire a temporary brightness lease after cleanup has returned.

Native Home sizing, faded-content capture guards, no-mirror rendering, alpha.80
endpoint smoothing, rotation restoration and the physical CLOSED veto remain.
No new global setting, device-state flag, physical power override or wake call
has been introduced.

## Verification and release limit

Deterministic tests cover missing first-opening samples, post-clear freshness,
bounded Home preparation in both directions, endpoint interruption, timeout
cancellation before remap, native-capture readiness, cover-only tail writes,
expired-writer rejection, all tail cleanup exits, and an in-flight write racing
cleanup. These execute the real controller and brightness implementation with
fake Android services; they are not optical tests. Final Android unit-test, lint,
APK identity, signing and archive checks are recorded with the delivery.

Pre-packaging validation passed: 685 Android unit tests in 126 suites (zero
failures, errors or skips); 804 controller checks, 52 brightness checks, 30 scene
checks, 60 task checks, 14 power checks, the shield cleanup harness, all preserved
B8 engine checks and its Android 36 compile, and the inner-stretch, window-shading
and motion-projection checks. Lint reports zero errors, 404 warnings and three
hints, unchanged from alpha.80's totals. These warnings are not a clean public
release certification.

The brief closing flash is not proven solved: the observed both-OFF transition
occurred during remapping, before endpoint cleanup. The brightness hold is a
bounded reassertion, not an OEM guarantee that a physical panel stays lit.
Alpha.81's changes must not be described as removing Samsung's forced OFF path.
The preserved firmware analysis in `FIRMWARE-DISPLAY-FINDINGS.md` documents that
distinction. AOSP likewise separates physical power state from brightness:

- https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/core/java/com/android/server/display/LogicalDisplayMapper.java
- https://android.googlesource.com/platform/frameworks/native/+/refs/heads/main/services/surfaceflinger/DisplayDevice.cpp

Public-release acceptance is still absent: repeated first-open after idle and
both slow/fast closing need visual confirmation, including the final cover
animation, native touch, rotation, pauses/reversals and lock/unlock. No connected
handset was available for this build. Do not publish it as a confirmed cure.
