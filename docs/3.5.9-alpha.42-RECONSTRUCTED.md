Incoming-display animation continuity fix, based on the preserved alpha41 source at 9b90a9195634e5be7e8e93776e788ed3506fbacf. No original-source equivalence or handset pixel proof is claimed.

## Evidence from the alpha41 test

The report contains static screenshot shield lifetimes of 729, 971, 1282 and 2604 ms. In session 54062753 the incoming primary continued drawing beneath the shield: commits increased from 54 at elapsed 54064774 to 95 at 54065776. The shader was not globally stopped during that interval; the retained frozen shield is a concrete explanation for an apparent frozen incoming animation. The trace is software evidence, not a measurement of visible pixels.

The cover primary also briefly reported the inner task configuration (933 x 704 dp instead of 475 x 751 dp). Native task geometry and post-remap window readiness must therefore remain release requirements. The supplied composition ZIP contained status text, not images: comparisons are intentionally paused while the standard-animation test switch is on.

## Changes

- Separate static-shield removal from native-app handoff completion. With the separate standard-animation test enabled, a fresh, correctly mapped native-panel image committed in the animated presentation can uncover that presentation as soon as the incoming primary is ON and committed. Both panel composites must be ready during the middle of a fold. At a native endpoint the outgoing panel may be OFF; the correctly mapped primary must still be ready. Source placeholders, stale frames, wrong mappings and old sessions cannot authorize this removal.
- Retain the opaque animated app composite while native task geometry and HAS_DRAWN settle. Completing a handoff or starting a reversal still requires the existing native checks and confirmed shield removal. Cancellation uses the same separation without reasserting Android's canceled power request. Lock, heartbeat, transition, thermal and power-lease bounds remain in place.
- Timestamp window-readiness results when the worker completes the check, before main-thread delivery. Require checks to start after primary verification. Two distinct successful observations at least 100 ms apart are still required, and the latest must be no older than 250 ms. A pending query can preserve a prior success for a bounded 750 ms gap, avoiding repeated resets with normal 300–500 ms query intervals. Failed, mismatched, overlong and out-of-order observations cannot authorize completion.
- Add PRESENTATION_UNMASK_SUBMITTED and raw/visual/committed angle diagnostics to distinguish static coverage from renderer progress. Capture export reports explicitly state when standard animation pauses image comparisons and preserves the remaining fold budget.

The normal Windowed Glass shader, saved stretch, blur, glass strength, compression, easing, smoothing, placement and AA controls are unchanged. The extra test switch remains default-off and preserves its saved value. The plain screenshot test keeps its previous shield-release behavior. No live mirrors, per-frame captures or new polling workers are introduced. Reduced waiting is the intended optimization; no CPU/GPU improvement is claimed without handset measurements.
