# 3.5.9-alpha.31-reconstructed-local

Request: retain alpha30's successful splash protection, temporarily remove the folding animation in BOTH selectable modes, and address the brief legacy destination blackout before restoring animation.

## Changes

- Both screenshot routes draw plain retained app images. Saved animation settings remain intact; no hinge shader, fade, dimming or animation loop is used for these images. Continuous glass capture and extra coordinated pixel probes are disabled for this comparison. Coverage/readiness checks remain active.
- Legacy exact-task routing requests focus once if the selected task is verified on D1 while Home still owns focus on D0. It never restarts the activity for focus and never takes focus away from another app/Recents.
- Legacy endpoint recovery no longer treats transient noninteractive state or a timeout as permission to return the task to an OFF, wrong-physical, or wrong-sized D0. It waits for unlocked, ON, destination-sized physical mapping, including restore retries. Reversal to the original endpoint updates the expected physical panel and size.
- Legacy requests one bounded Samsung per-display ON lease near the final 12 degrees, with a maximum five-second duration, early release after mapping/task return, and cancellation on lock/other sleep/stop. It uses the existing inspected per-display API; acceptance is logged separately from actual power state. It does not reassert concurrent display requests after Android cancellation.
- Legacy preattaches transparent hosts and captures the exact D1 app once (bounded retries for dark/unready content). Plain snapshot coverage follows the incoming physical panel across D1 to D0 near the endpoint and reveals native content immediately after two exact-app readiness samples. Five-second coverage deadline, 30-second preparation bound, connection-loss cleanup, lock cleanup and stale-callback rejection apply. Missing capture means no fabricated black mask. A physical display-OFF interval cannot be covered by an overlay.
- Coordinated Android-cancellation coverage budget increases from 500 to 1800 ms so the alpha30 guarded primary snapshot refresh can finish. Existing fallback, lock, thermal and cleanup paths remain bounded. The unrelated brightness fallback retains its 500 ms budget.
