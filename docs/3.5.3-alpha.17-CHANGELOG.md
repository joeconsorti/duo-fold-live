# 3.5.3-alpha.17 — screenshot endpoint readiness and rotation recovery

The screenshot baseline returned the app to inner D0 while its dimensions still
reported 1248x1972. The same physical display subsequently became 2448x1848.
This build requires the incoming physical ID, ON state and captured destination
size before the existing opening endpoint task return. Size comparison permits
rotation. The expected dimensions come from the secondary display, refreshed
while the fixed panels are ready. The existing 1800 ms recovery deadline and
mode/lock cancellation remain; fallback return is explicitly logged as recovery,
not readiness. Closing task routing is unchanged.

The developer window-first screenshot route also enables saved fixed-rotation
policy reconciliation after posture/settings restoration and after failed
verification passes. Previously these passes only observed a mismatch. The
original values remain journaled, physical-panel mapping is rechecked, and two
consecutive successful readbacks remain required before deleting the journal.
The reconciliation marker is persisted so crash recovery finishes the same work.
A successful error-path restoration now replaces stale error status in this
route. Failures report physical panel, expected policy and actual policy.

Normal handoff defaults and power experiments are unchanged. This addresses
app-return ordering and rotation recovery; it does not prevent the platform's
panel OFF transition. No handset/optical improvement is claimed.
