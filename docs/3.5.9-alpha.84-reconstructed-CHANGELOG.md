# Alpha.84 local readiness update

Based on alpha.83 (9d93c22). Install over the existing local test app. The update retains the saved Advanced controls from alpha.83 or alpha.82.

In Duo Mode with destination-only bars, Home readiness precedes bar capture. In the reported alpha.82 closing session 524236956, the first destination image committed at 524238362, handoff completed at 524238520 and the bar capture was timestamped 524238554. This is an example of software event ordering. No alpha.83 handset timing sample was supplied for this update.

* Each exact capture now splits each WindowManager dump into window records once. The selected-task, owner, splash, fade and wallpaper checks use the same records. Before and after capture still use independent dumps.
* On the stock-wallpaper Home route, both capture requests still go out together. A faded or missing launcher now rejects the attempt before Duo reads the composed screen image into CPU memory. The completion releases unused buffers, including late callbacks. An accepted pair still passes the same opacity and pixel agreement checks.
* For a direct Home snapshot on D0, a successful post-capture window check can supply the first readiness observation. Duo verifies committed display power and matching physical panel, dimensions and rotation after that check. The observation belongs to the same session, task, capture revision and active primary check. It must meet the existing age and duration bounds. The exact retained image must commit on the primary. The controller still requires a second independent successful observation at least 100 ms apart. Missing or stale evidence takes the normal readiness path. The diagnostic line includes observation=capture-post-guard when this path is used.

The alpha.83 screen-switch thresholds and routing implementation remain the baseline. Android still controls when the destination launcher draws.

Validation includes paired-capture and pixel-oracle tests, the handoff harness, Android unit tests, and an APK identity and signature check. On a synthetic 59,404-byte, 35-window report, one host JVM run measured median Home guard processing at 5.03 ms on alpha.83 and 2.50 ms on alpha.84. This measures parser CPU work on the host. Total screen-load improvement on the SM-F971U has not been measured.
