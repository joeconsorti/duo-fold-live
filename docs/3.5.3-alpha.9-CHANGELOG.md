# 3.5.3-alpha.9 — staged incoming-primary handoff

Continues the new alpha.4-derived lineage from ci-117-1. Main remains 3.5.2.

Alpha.8 showed that the active app stayed on display 0 while display 1 exposed a separate Samsung launcher. This build first retains the outgoing primary until the screenshot is committed and both panels are ready, then directly replaces the concurrent request with the incoming-primary state. There is no explicit cancellation between those two stages. Android's actual panel remap and optical continuity still require device verification; this is an experimental fix, not a confirmed blackout-free handoff.

The pre-attached secondary window renders the outgoing screenshot plus existing animation only when its current physical display ID matches the capture. The rebuilt primary overlay exposes the live incoming app with animation. Screenshot labels remain enabled for this diagnostic alpha. The outgoing secondary screenshot must commit before it is considered ready. Remap or readiness failures release the override after a bounded wait.

Closing startup now requires an angle at least 12 degrees below the configured open endpoint (160 degrees with the default 172). Opening retains the near-closed startup. This avoids the repeated near-open sessions observed in alpha.8. Rotation, wallpaper and animation shader geometry are unchanged.

Task records are shorter so earlier transition events survive in the report. Window snapshots prioritize Duo, launcher, taskbar and all secondary-display windows rather than filling the trace with unrelated primary overlays.

## Device test
Install over ci-117-1. Keep animation and both screenshot toggles enabled. Start inside Duo on the cover, unfold once, and check that the inner panel displays Duo rather than Home. The FROZEN COVER label should stay outside. Fold once past 160 degrees: FROZEN INNER should stay inside while the cover displays the live app. Note any blackout or lock screen, then copy the status report promptly (24-hour health history can be omitted). A reversal before reaching the endpoint is also useful after the one-cycle test succeeds.
