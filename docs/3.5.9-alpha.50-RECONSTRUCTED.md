## Problem and resulting behavior

The user reports animation start, freeze, Home flash, then resumed animation in
both folding directions. Earlier builds deliberately placed whole-display static
screenshot shields above their animated app windows during primary promotion.
Alpha48's animated opening showed shieldAgeMs=354; earlier alpha41 traces had
continued frame commits underneath a retained shield. Those are software intervals,
not measurements of visible freeze time. The exact Home-flash path was unproven:
window/root visibility lag, sampled stack remapping, and Home in the whole-display
shield capture were candidates. Alpha49 retained that architecture.

On Android 15+ the coordinated B8 route now uses independent physical-panel app
buffer producers throughout preparation, task movement, primary promotion, and
native readiness. Normal primary promotion allocates no static shield and takes
no whole-display handoff screenshot. Android 14 retains the previous window/shield
backend. Existing normal/legacy routes and saved effect controls are unchanged.

Each physical panel has an owned parentless root and app child, with three bounded
HardwareBuffers rendered by HardwareBufferRenderer using the existing glass shader.
The producer retains physical dimensions across logical display swaps. Root
visibility and the rendered buffer are submitted together. Readiness uses the
transaction-completed callback, not the old SurfaceView child-commit followed by a
separate WindowManager alpha request. Completed presentation is still not proof of
unoccluded physical pixels.

Shell code exchanges both root layer stacks in one transaction after observing a
complete, unique physical-ID/stack pair. Missing/duplicate mappings retain existing
layers and invalidate readiness; they never detach a missing panel. Opaque black
guards cover the maximum panel extent during the non-atomic interval between
Android's remap and our retarget. This is still sampled mapping: transient wrong
geometry/black edges cannot be ruled out without handset observation. It is not an
atomic integration with Samsung's display transaction.

No mirror graph, continuous screen capture, input window, or extra power reassertion
is introduced. Exact selected-task captures, destination validation, brightness,
native task/HAS_DRAWN checks, hysteresis, cancellation recovery and alpha49's quick
reopen behavior remain. Root lease expires after 750 ms without controller renewal,
with a 30-second scene bound. Cleanup detaches roots from all stacks before allowing
late app submissions; it waits for completion before releasing route ownership.
A two-second cleanup watchdog terminates only the owned shell helper if removal
cannot complete. Lock/disable/freshness guards remain.

Buffer reuse requires the compositor release fence. Fence waiting runs off the UI
thread; a timeout retires the buffer rather than overwriting it. Pending GPU work
cannot acknowledge or reshow a closed scene. Published app images remain opaque.
Startup eligibility is latched at the independent render submission, so a visible
first animation cannot be changed to a plain frame merely because its completed
callback arrived later. Mid-session rotation that no longer matches the physical
renderer does not acknowledge readiness and enters existing bounded native recovery.

## Diagnostics

Armed composition evidence now runs with standard animation/glass enabled on the
independent route. BEFORE_PRIMARY, AFTER_PRIMARY and CANCEL_RECOVERY observations
are bounded to four samples per armed episode and six episodes per ten-minute arm.
Each sample saves the source image and up to two physical-compositor screenshots
with timestamps and selected-task window observations. Moving images get no pixel
comparison/pass verdict. Missing API, protected content, mapping change and timeout
are explicitly inconclusive.

The physical capture uses ScreenCaptureInternal/ScreenCapture DisplayCaptureArgs
and a physical display token. It intentionally does not fall back to WindowManager
subtree capture, which may omit independent root layers. The images remain local
until the user exports them. No actual static shield exists to sample on this path.

## Validation and limits

- Android compilation and existing unit-test delivery suite.
- Real controller against fake platform: 386 checks, including 49 additional direct
  route checks for both directions, animated/plain content, deferred mapping,
  native readiness, no shield allocation, reversal, cancellation and delayed cleanup.
- Real independent-root implementation against fake compositor: 17 mapping,
  presentation callback and cleanup checks.
- Compiled production Kotlin buffer renderer against fake GPU/compositor: 15 checks
  for bounded buffers, combined root visibility/buffer submission, presentation
  readiness, delayed release fence, reuse, and late callbacks after close.
- Existing real shield cleanup and 25 brightness checks retained for compatibility.
- Existing compiled production geometry replay retained.

No phone is connected. These checks establish code behavior and resource protocol;
they do not certify Samsung compositor output, smoothness, color, battery cost, or
absence of the reported Home flash. Test the same settings with slow/fast opening,
closing and immediate reversal. Arm composition capture with glass left ON before
the test, then export diagnostic text and images if any pause/flash remains.
