# 3.5.9-alpha.29-reconstructed-local (1282)

Based on alpha.28 commit 96bbe4fe89ee34d2227da6178a611dd52de36bbf.

The alpha.28 report contains transient unknown physical identity and incoherent presentation geometry during the last close. The renderer explicitly posted a black buffer on that path. It now checks identity, layout and capture exclusion before acquiring a canvas, retains the previous buffer during uncertainty, invalidates readiness and retries after 16 ms. If the acquired canvas still has the old buffer dimensions, app content fills it without a commit acknowledgement; it retries for the exact geometry. This cannot preserve a surface destroyed by the platform and is not a guarantee of visible continuity.

The first opening logged PRESENTATION_STALE_AT_ENDPOINT followed by immediate cleanup. Phase 2 and phase 3 now use the existing bounded native fallback at such an endpoint: release the device-state request, restore the selected task when present, retain presentation for at most 500 ms, and require fresh native primary geometry, app readiness and matching presentation commit before early cleanup. An unavailable secondary presentation no longer forces immediate removal of primary coverage. No extra screenshot shield is allocated by this fallback and no concurrent power request is reasserted while waiting.

Validation: 122 deterministic controller checks plus bridge cleanup and brightness suites passed. Added coverage for loss of secondary readiness after an opening handoff, waiting for a fresh primary acknowledgement, and the existing bounded timeout. Gradle unit tests and APK assembly run through tools/build_local_test.py. Handset visual behavior remains unverified.

Scope: two source-grounded continuity fixes. Fast-cycle remap latency, diagnostic capture overhead, Android surface replacement and app relayout costs may still produce glitches. Historical SurfaceFlinger crashes and ChatGPT heap failures in the report are not attributed to these four current Duo episodes. Incoming black capture retry, physical identity guards and commit freshness checks remain enabled.
