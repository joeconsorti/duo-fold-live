# Duo Fold Live 3.5.9-alpha.6

Coordinates the experimental Live B8 presentation across app movement and primary promotion.

- Captures the exact outgoing fullscreen app and commits opaque app + glass windows on both built-in displays before moving the task. The same hinge-driven presentation continues through promotion.
- Arms the B8 bridge before moving the app. Once its initial shield commits, hides only its frozen buffers so the retained WMS mirrors carry the animated windows. Keeps the existing physical brightness, display power, geometry checks and removal watchdogs.
- Reveals the primary after verified task geometry and a fresh, matching physical-primary presentation commit, replacing the additional fixed 150 ms reveal delay.
- Revalidates the exact incoming app window as drawn after each promotion before replacing the held image with live captures; rejects older frames from before that validation.
- Retains each outgoing panel's app image independently of the short bridge, until endpoint/cancellation/disable/lock/stale input. A separate 30-second session bound prevents indefinite holds.
- Pauses and drains the ordinary screen capture producer before attaching B8 mirrors, then resumes only after confirmed mirror removal. This avoids capturing the bridge back into its own input.
- Adds bounded presentation status and readiness/ordering tests. Legacy expansion and preview ownership remain suspended during B8.

The developer B8 switch remains off by default. This is a signed prerelease, not a stable-channel change. Existing settings and the standalone Lab 0.5.11 baseline are retained. No screenshots are persisted.

Validation: deterministic controller ordering/readiness/cancellation tests, real bridge delayed-commit cleanup tests, brightness tests, baseline fingerprint checks, Android unit tests and lint/build/signature verification in CI. Software commits do not establish visible-pixel continuity; the handset sequence still needs visual confirmation.
