# 3.5.3-alpha.16 — closing cover direct-power experiment

Alpha.15's opening trace confirms its prepared frame committed before the inner
state request, but still records a panel OFF interval. The closing trace separately
records an explicit app cancellation, transition from concurrent cover state 5 to
native closed state 0, then cover OFF and ON without a physical-primary change.
The sampled OFF-to-ON span is 156 ms; it is not an optical measurement.

## Change

Adds **Closing cover power pulse (experimental)** to Developer settings, OFF by
default. Use with Dual-screen screenshot handoff OFF and Cover preview ON.
The existing Samsung ON override switch retains its screenshot-only meaning.

After a normal closing endpoint release decision, an independent worker watches
for at most 1200 ms. Only when current/base device states both report native closed
state 0, the same verified cover remains D0, D0 reports OFF, and fresh closed input
and interactivity remain valid, it calls `IDisplayManager.requestDisplayPower(0,2)`
once. The worker requests `(0,0)` after 250 ms (or earlier on cancellation) to
reapply the current framework power request. There is no repeated ON loop,
concurrency extension, new task route, or change to opening/preview timing.

The exact `(int,int)` API is present in the user's firmware inspection report.
The inspected AOSP implementation passes the state directly to the primary display
device; state UNKNOWN/0 reapplies `mDisplayStates[displayId]`. The exact Samsung
Android 17 implementation of this method is not available locally, so acceptance,
restoration, and visible benefit remain device-test questions. A returned boolean
is logged verbatim and does not establish optical visibility or continuous power.
Reference implementation: https://github.com/aosp-mirror/platform_frameworks_base/blob/main/services/core/java/com/android/server/display/DisplayManagerService.java

## Read the result

The short report includes a distinct closing direct-power trace: arm, sampled
D0/current/base changes, ON return value and latency, policy restoration return
value, maximum sampling gap, and stop reason. It continues sampling through the
1200 ms window after cleanup, so a second OFF transition can be detected.
Opening OFF intervals and full device sleep are outside this experiment.

Compare several full closes with the new switch OFF, then ON, keeping other
settings and foreground app unchanged. Copy the short report after each group.
