# Alpha.62 reconstructed — Duo default and shared effect resolution

Version code 1315. Based on alpha.61 commit 56abebe. Recovery target remains
alpha.20; this is reconstructed source, not a claim of original-source or handset
equivalence. Private APK only; no GitHub publication is requested.

## Requested changes

- Screenshot Mode is now **Duo Mode**, listed first and selected once on install
  or upgrade. Live Screen is now **Live Screen Mode (Legacy)**. Later explicit
  selections survive process restarts; changing modes retains shared adjustments.
  The internal transport identifiers remain unchanged.
- Replace Full-resolution glass in the same Fine-tune location with a stepped
  **Glass / effect resolution** slider: 25%, 50%, 75%, 100% of each screen dimension.
  Both modes start at 25%, the approved screenshot profile (one-sixteenth of
  native pixels). The retired boolean is removed. Later resolution selections
  persist across modes and restarts.
- Both renderers use one sizing policy, including the direct physical screenshot
  buffer, logical fallback buffer and live SurfaceView. Lightweight blur no
  longer overrides a selected resolution. Advanced 4x supersampling remains
  independent and doubles each selected dimension, as the control help explains.
- Shared defaults are 40% glass strength and 150% blur. These values were already
  used by both modes; the old help incorrectly described glass as 100%. Correct
  the help, centralize the glass default, and retain existing user tuning. Mode
  changes do not create separate effect profiles or reset glass/blur.

The source image/capture sizes, shader blur radius, sampling, shading, gyro math,
hold behavior, handoff and startup scheduling are unchanged. Render resolution
changes only the effect's raster dimensions; normal screen content is unaffected.
No claims are made about equal perceived blur over different live/snapshot content.

## Validation

Unit coverage checks the one-time upgrade default, later legacy selection,
restart persistence, all four resolution choices on both physical panel sizes,
integer rounding, malformed settings, independent supersampling, and preservation
of glass/blur edits when switching either direction. Both rendering routes call
the same production sizing policy.

Use tools/build_local_test.py from a clean committed tree for unit tests, APK,
source archive, Git bundle and hash manifest. Release validation uses
testGithubReleaseUnitTest, lintGithubRelease, assembleGithubRelease and
tools/check_release_outputs.py. Existing shader/controller/buffer checks remain
applicable. No connected handset is available; actual rendering detail, thermal
cost at higher resolutions and visible presentation still require device testing.
