# 3.5.9-alpha.57 reconstructed local — remove animation startup veto

Version code 1310. Recovery target remains alpha.20; reconstructed source does
not establish equivalence with the unavailable original implementation.

The user reports alpha56 Home transitions are much snappier and explicitly asks
to remove any intentional suppression of animation on fast folding/unfolding.

B8AnimationStartPolicy previously permanently skipped a physical panel's animation
if its first frame arrived after 500 ms, traveled more than 30 degrees from the
session's initial angle, or reached an endpoint before its first commit. Those
vetoes are removed, including commit-time rejection based on elapsed time/travel.
The policy now depends only on the user-enabled animation setting and a finite
current hinge angle. Invalid input does not permanently disable later valid input.
Renderers keep their existing current-angle initialization and smoothing; there
is no replay from the start of an animation. Diagnostics no longer claim late
animation is intentionally skipped.

This applies to both Home and app coordinated presentations, as explicitly
requested. The alpha56 Home endpoint bypass remains: if the motion finishes
before a presentation is ready, native Home is uncovered immediately. That
natural endpoint cleanup is independent of a speed veto. No animation can be
promised to appear in a motion that finishes before its first frame is ready.

App task movement, primary thresholds, snapshot selection, readiness verification,
cleanup, shaders, brightness, and renderer methodology remain unchanged. No
speculative app-readiness reduction is included. Inspection shows apps use the
shell exact-capture route rather than the Home accessibility screenshot API;
the Home screenshot cooldown fix therefore cannot simply be copied. Candidates
for later measured optimization are capture/mip processing, painter setup, and
repeated native-readiness queries, while preserving same-task/physical-display/
rotation checks. Current app timing evidence is needed to rank them.

Validation: eight policy regression tests cover fast opening/closing, travel
between submission and commit, reversal, endpoint/nonfinite recovery, independent
panels and the disabled setting. The complete Android unit suite and production
controller/cleanup/brightness/scene/task fake-platform checks are run for delivery.
No handset or optical rendering test was performed here.
