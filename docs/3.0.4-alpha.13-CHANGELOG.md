# 3.0.4-alpha.13 — Temporary photo during unlock handoff

Alpha.12 visibly improved the wallpaper but its trace showed Home attachment unavailable before unlock, followed by a success acknowledgement 6 ms after USER_PRESENT. The photo then appeared in the correct hierarchy. That callback interval is not a measurement of visible flash duration.

This experiment prepares a second photo under a negative-Z anchor attached to the focused full-screen SystemUI window while keyguard is locked. It uses the existing authorized accessibility connection and changes only Duo-owned surfaces. The photo remains hidden while Android reports keyguard locked. A bounded 8 ms state check can reveal the prepared photo after unlock, before Home attachment completes. Home placement and bridge hiding are submitted together; the temporary surfaces are then released.

Only arm after Home was observed active within 1.5 seconds before screen-off. Disarm on another active app, successful Home handoff, a new sleep session, shutdown or attachment failure. A separate 750 ms expiry after the first unlocked observation prevents the bridge from persisting even after fast polling stops. No input surface, focus, rotation or animation settings are changed. Window-event reattachment no longer adds an intentional 32 ms delay.

Trace markers record bridge preparation, visibility, handoff and timeout. Full-screen SystemUI accessibility availability and its compositor lifetime remain device-dependent; the experiment falls back to alpha.12 behavior if unavailable. Lock-screen appearance, Home icons, app-unlock and both panels need handset checks.

Validation: 13 focused tests cover launcher selection, attachment cancellation/late callbacks and bridge lock/timeout/relock policy. Java compilation against Android 36 passed; CI runs the full release tests, lint, assembly and signing.
