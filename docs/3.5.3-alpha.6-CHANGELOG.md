# 3.5.3-alpha.6 — screenshot window-first startup

Continues the new alpha.5 native-underlay test (ci-114-1), directly descended from approved alpha.4. No discarded alpha.5–alpha.8 code was reused.

Joe's alpha.5 findings: both panels activated without observed blackout. Revealed inner content remained a stretched cover-style launcher, with incorrect drawer layout and “App disabled” on launch. Native inner layout and app routing remain unresolved. The supplied screenshot was explicitly withdrawn as evidence.

## Priority: initial screenshot-mode blackout
- New default-OFF developer toggle: **Screenshot window-first startup (experimental)**. Requires **Dual-screen screenshot handoff ON**, plus normal animation ON.
- Attaches a non-touchable secondary window before the concurrent-state request, using the Camera test's display/window-context ordering.
- Requires the outgoing capture and attached secondary window. Retains the current physical primary (cover on opening, inner on closing), rather than immediately requesting the opposite primary as the original screenshot path does.
- Displays the held outgoing screenshot and existing animation on the destination; this is a transitional image, not a native inner-layout claim. Primary animation also uses the held frame.
- Uses Camera's inner-concurrency flag 4 when starting inner-primary; outer-primary retains default flags.
- Existing endpoint release, lock/stale-angle/disconnect cleanup remain. Added window-loss and physical-identity checks and a 30-second session limit.
- Final endpoint remapping may still flash; this build targets initial activation only. Native content routing and a final blur reveal are deferred.
- Original screenshot path remains available with the new toggle OFF. Public main, normal live mode, approved shader curves, wallpaper and rotation are unchanged.

3. Return Home, pause fully closed briefly, then slowly unfold. Observe initial inner-panel activation separately from the final fully-open native switch.
4. Repeat from fully open while folding. Note any initial flash, held image/animation, and final-close flash separately.
