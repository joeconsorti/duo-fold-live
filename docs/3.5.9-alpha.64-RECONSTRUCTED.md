# Alpha.64 reconstructed — Duo Mode multitasking

Version code 1317. Private candidate based on alpha.63; recovery target remains
alpha.20. No GitHub publication or original-source equivalence is claimed.

Duo Mode previously admitted only an exclusive fullscreen app root. Its snapshot
and readiness guards also rejected any other visible task. Split-screen groups
therefore never reached an animated presentation.

Observe visible app leaves on the native primary as one workspace, including two
and three panes under an organizer root. Capture that composition with the existing
overlay/photo exclusions and normal Windowed Glass renderer. Never move, reparent,
focus, close or resize a member of the workspace. Android owns native split layout
and cover-screen behavior. The existing Home native-layout handoff machinery is
shared for group routing, while Home pixel composition remains separate.

Workspace capture requires every selected pane to be HAS_DRAWN, rejects other
on-screen task windows and starting/hidden panes, and validates task membership,
activity/user identities, geometry, panel identity and rotation before and after
capture. Secure/protected capture remains prohibited. The native destination is
captured after verified primary remap; no split app is prepared on display 1.
An oversized/stale pane layout cannot certify destination readiness.

At full endpoints, remove group coverage without waiting for another capture.
The existing 1.25-second pause, 5-degree resume threshold, ease/dissolve and
rotation hold apply unchanged. A native collapse to an original member is allowed;
the controller remembers the group for the next episode so that member is not
extracted when unfolding. A different app or Home selection replaces that memory.
The memory is process-local, not a persistent reconstruction of Samsung app pairs.
Unknown membership or unsupported layouts fail back through existing cleanup.

Live Screen Mode's rendering and handoff path are unchanged. No style, default,
resolution, blur, gyro, rotation or hinge-threshold settings change in this build.

Validation includes production controller lifecycle tests for workspace handoff,
readiness, pause/resume and fast endpoint cleanup; production task-routing tests
for two/three panes, logical remaps, native single-pane collapse and restoration,
wrong app/user, stale geometry and keyguard rejection; unit tests for ordered
membership and all-pane window readiness. Existing fullscreen and Home tests stay
in place. Build with tools/build_local_test.py from the committed clean tree and
preserve APK/source together. No Fold is attached: Samsung's two/three-pane native
layout transitions still require handset confirmation; software commits and
HAS_DRAWN do not prove visible pixels.
