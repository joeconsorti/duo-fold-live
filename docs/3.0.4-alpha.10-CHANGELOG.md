# 3.0.4-alpha.10 — Home-anchored photo experiment

The alpha.9 capture showed Samsung moving its live wallpaper beneath a higher transition root while Duo's photo remained in the lower wallpaper area. Keeping that lower photo loaded did not fix the flash.

This build adds a different placement: a bufferless negative-Z anchor attached beneath the default launcher's window content using the existing UiAutomation accessibility connection. An independent, opaque custom-photo surface is positioned relative to that anchor, above the lower wallpaper transition but below launcher content. Relative positioning avoids inheriting the launcher's fade opacity/transform; hidden-state inheritance is retained. Only Duo-owned surfaces are changed.

- Select only application windows belonging to the resolved default launcher, with near-full-display bounds on built-in display IDs 0/1. No node text or view tree is inspected; the root package identifies the launcher.
- Prepare the placement when Home becomes available and retain it through sleep/unlock. Reattach when the launcher window changes, refresh geometry across panel remaps, update when the selected photo changes, and remove when wallpaper stops.
- Unsupported APIs or failed attachment retain the existing native/window wallpaper renderer. Background reports include Home-photo attachment status; alpha.9 unlock capture remains available.
- Display capture progress beside its button as well as below the previews.

This is an experiment, not a confirmed fix. Visit Home once after installation, then test repeated lock/unlock on each panel, Home icons/touch, opening other apps, and fold/unfold. A newly recreated Home window may require a fresh attachment; the next trace will show its timing. Launcher hidden-state behavior and lock-screen appearance need handset verification. Existing animation, rotation and Samsung wallpaper bindings are unchanged.

Validation: four launcher-window geometry selection tests pass locally; changed Java sources compile against Android 36 with compile-only dependency stubs. Full release tests, lint and signing run in CI.
