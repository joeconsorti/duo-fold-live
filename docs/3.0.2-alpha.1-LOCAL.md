# Historical local review notes — incorporated into 3.0.2

Confirmed issues addressed:
- Existing installs can reopen required wallpaper setup from Connection & setup, including reapplying when a saved verification flag exists.
- Setup helpers use the build version to avoid reusing an older helper after updates; stalled setup has a bounded timeout and retry.
- Root-mode wallpaper setup gets an explicit ADB-mode explanation before binding.
- Main status displays the actual angle-reader state instead of attributing every missing angle to Shizuku connectivity.
- Open Shizuku failures are visible; fork users are directed to open their manager manually.
- Wallpaper authorization uses a visible dialog; periodic background status no longer erases action feedback.
- Accessibility instructions include the missing-menu reporting path.
- Connection reports include firmware and reader counters for received wallpaper logs, parsed responses, and timestamp rejection. No broad log capture added.

Not confirmed fixed: regional/Ultra zero-angle responses; post-1.7 regression; Fold 5/6/7 compatibility; fork connection delivery; repeated flashing, cover-only failures, restart locking. Need on-device reports. Angle parser unchanged from v1.7.0; animations and wallpaper rendering backend unchanged.

Pending follow-up: wallpaper UI consistency, USB/Android Auto disconnect recovery, fresh wallpaper binding readback rather than only saved setup verification. Do not claim all bugs fixed.

Release of these changes as 3.0.2 was subsequently authorized.

## Follow-up review
Compared v1.7.0 with current AngleReader, AngleParser, LiveAngles and WallpaperSetupService. Parser, logcat filter, anchor command routing and wallpaper profile logic are unchanged; no proven shared regression identified. Explicit Repair now forces reapplication of both HOME wallpaper bindings even when configuration matches, instead of silently skipping both writes. Normal first setup retains its existing conditional behavior. This repairs a retry gap, not a demonstrated universal zero-angle fix.

Shizuku+ releases link and uninstall-original-first instructions added to setup, troubleshooting, and Connection & setup. No rendering or animation changes. These follow-up edits are included in 3.0.2.

## Compatibility/setup audit against v1.5.4 and v1.8.0-alpha.1
- Confirmed startup regression: DuoApplication (absent in 1.5.4) populates standalone preferences before MainActivity calls FirstRun.required. FirstRun treated any preference as legacy setup, skipping the wizard on fresh installs. Automatic defaults now do not count as legacy user data; real settings and existing onboarding markers remain preserved. Added regression coverage.
- Enable animation now opens guided setup if overlay access or the accessibility service is missing. Missing-angle status exposes wallpaper repair and reports directly, including for previously skipped installations.
- Secondary animation and legacy photo host rejected every resolution except the original Fold8 dimensions. Internal display type now permits other panel dimensions, retaining old dimensions as fallback if type inspection is unavailable. Still limited to the existing 0/1 display routing; not a TriFold implementation.
- AngleParser, wallpaper logcat filter/freshness checks, wallpaper command anchors, accessibility XML and required overlay/Shizuku declarations were not removed or tightened between the known-working tags and current source. Poll cadence changed, but reports showing regular polls and zero replies do not establish cadence as a cause.
- Wallpaper profile still assumes Samsung FoldInteractive/video_001.mp4; a matching binding does not prove working firmware angle logging. Android17 remains required by the existing Samsung API path. Regional/Ultra angle delivery and older OS support remain unverified; do not claim universal compatibility.
- Reviewed changes to setup, startup defaults, background recovery, helper versions, manifest, permissions, command delivery, parser, photo host and display selection. Animation/fade/shader changes remain preserved. These code checks cannot establish which failure occurred on a reporter's phone without its new diagnostics.
