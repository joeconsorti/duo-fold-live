## Requested visual refinement

The user reports alpha53 now shows the complete cover Home icon layout. During
opening, its temporary portrait cover image sits on the right of the inner panel
with black space on the left. They requested a more coherent frosted appearance
until the native inner Home is ready, while preserving ordinary in-app behavior.

This build uses one full-width, heavily defocused Home preview. It avoids two
recognizable copies of the icon grid and the black half-panel gap. The preview
draws the already accepted outgoing cover composite across the inner panel with
strong blur and a subtle light/dark frost tint. It is a temporary visual treatment,
not a native inner launcher layout or a live mirror.

## Behavior and scope

- Enabled only for a Home session whose source is the narrow cover panel and
  whose destination is the wide inner panel. Aspect classification is independent
  of portrait/landscape rotation. Ordinary apps, closing Home toward the cover,
  the cover renderer, and Recents routing keep their existing paths.
- Until a validated native inner snapshot matches physical identity, logical
  dimensions and rotation, the opaque frosted preview fills the entire inner
  panel. The existing source image still has its original identity: it cannot
  qualify as a native-panel capture or trigger native readiness.
- When the native image arrives, the unchanged native Home renderer and saved
  Windowed Glass settings draw at the current hinge angle beneath the preview.
  The preview dissolves with smoothstep opacity over 180ms. It does not replay
  hinge samples or restart on subsequent native frames. If native Home is ready
  on the first draw, the temporary preview is skipped completely.
- Cosmetic redraws continue through the short dissolve even if the hinge pauses,
  using the existing rate limit and one-pending-buffer gate. At a raw hinge
  endpoint the remaining dissolve is skipped once native content is available.
  Missing native content never becomes transparent merely because time passed.
- No controller, power, brightness, task move, native-release deadline, capture
  route, alpha-content rejection, screenshot exclusion or shared glass shader
  is changed. The new visual layer supplies no readiness acknowledgement and
  adds no controller wait. Existing endpoint cleanup may end the effect early.
- The effect is drawn inside the existing scene buffer. It creates no mirror,
  extra display surface, screen capture, or full-panel CPU bitmap. It reuses an
  existing coarse mip (longest side <=48px), or makes one small mip if the source
  has none, then applies a cached RenderNode blur. The node is reused per physical
  inner panel and released on session cleanup or geometry/rotation replacement.
  Published pixels are not manually recycled while a GPU frame may refer to them.
- The Home inner diagnostic reports the preview's last draw stage and opacity.
  A native frame underneath a dissolving veil is not proof of fully visible
  native pixels; submitted/committed state and camera evidence remain distinct.

selection in both orientations, missing-native retention, native-ready-first
skip, 180ms convergence, no restart, endpoint shortcut and invalidated layout.
The clean delivery build reruns all unit tests from this committed source.

Existing controller 412, brightness 25, scene 19, task-routing 24, GPU-buffer
lifetime 15 and geometry 19 checks plus delayed cleanup are retained. These
checks use fake Android/compositor implementations, not optical measurements.
No handset is connected, so blur appearance, frame time and the observed
transition still require testing on the user's SM-F971U.

Install the APK as an update. First open from folded while on Home without
diagnostics, slowly and then faster; pause mid-opening to check the dissolve.
The cover Home should behave as in alpha53. If the new inner effect glitches,
arm the existing Home inner sequence and save the report/ZIP. Ordinary app
fold/unfold should be checked as a regression, not retuned.
