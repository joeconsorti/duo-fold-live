# Alpha.61 reconstructed — shared motion glass and faster screenshot startup

Version code 1314. Based on alpha.60 commit 443e1d0. Recovery target remains
alpha.20; this is reconstructed source, not a claim of original-source or handset
equivalence. This candidate is a private APK; no GitHub publication is performed.

## Requested behavior

The top Folding Animation Style card now selects Live Screen or Screenshot Mode.
Live Screen is the fresh-install default; upgrades retain the user's saved transport.
Both use Windowed Glass. Plain Fade, Duo Classic, their rendering implementations,
and the legacy Classic/debug picker are removed. Startup migrates old appearance
preferences to Windowed Glass while preserving independent fold/unfold behavior,
transport, enabled state, glass intensity/blur and gyro settings.

Screenshot uses the existing MotionGlass sensor path, baseline, dead zone,
orientation mapping, sensitivity, inversion, smoothing and recenter control. Its
embedded shader now consumes those offsets just like Live Screen. Both physical
panels and the Home frosted preview use the same painter. Panel-specific enable
and sensitivity settings still apply; the cover experiment remains off by default.
The Live Screen sensor math, timing and Windowed Glass geometry are unchanged.

Tilt notifications request a screenshot redraw only when that panel's offset
changes. Changes during an in-flight buffer are coalesced and rendered at its
completion. Screenshot keeps its existing maximum 60 submitted fps and bounded
buffer ownership; all new listeners are removed when the scene closes.

## Startup work

- Request physical layer handles and prepare GPU buffers/shaders while the guarded
  source capture is running. Roots stay hidden until the fresh image's first draw.
- Allocate one buffer per panel before first presentation, growing only as needed
  to the existing three-slot limit. Never reuse compositor-owned buffers before
  their release fence signals.
- Wake prepared renderers directly from capture completion instead of waiting
  for another angle reply.
- Overlap Home's post-capture validation with bitmap composition/mip preparation.
  Both the original preflight and post-capture checks still gate publication.
  Rejection disposes the unpublished image and all derivatives; every attempt
  drains its validator before accepting another. The additional worker is bounded
  to one validation per active Home capture and performs no idle polling.

These changes remove serial preparation dependencies; they do not establish a
millisecond handset speedup. App handoff methodology, snapshot resolution, glass
amount, blur, hinge smoothing, 1.25 s hold / 90 degree choice / 5 degree resume,
fast endpoint release and capture pacing are retained. There is no fast-motion
animation veto or added cooldown. Home timing now labels overlapping build and
validation durations; they must not be added as serial costs. Renderer preparation
has a separate B8 RENDERERS_PREPARED trace, and first submitted content retains
B8 DIRECT_FIRST_PRESENT timing. Neither is optical timing.

## Validation

Production buffer replay: 18 checks, including lazy allocation, first-pixel/root
visibility ordering, pending release fences, early cancellation and late callbacks.
Production HomeFrames replay: 23 checks, including work overlap, no delivery before
validation, failed postflight cleanup, preflight rejection and failed-build draining.
These use fake Android APIs and do not validate GPU pixels or Binder firmware.

Shared gyro policy tests cover stationary-hinge updates, pending-frame coalescing,
neutral/disabled panels, malformed offsets, and unchanged Live Screen eligibility.
Settings tests cover old styles, both transports, restart and retained gyro/blur.
Shader geometry checks and all 665 controller lifecycle/readiness checks pass;
scene/task/brightness/power replays and the imported engine baseline also pass.

Build using tools/build_local_test.py from the complete committed tree. It cleans
stale classes, runs debug unit tests, builds the APK, and packages a source archive,
Git bundle and hash manifest. Release validation uses testGithubReleaseUnitTest,
lintGithubRelease, assembleGithubRelease and tools/check_release_outputs.py.
There is no connected handset; visual gyro behavior, first-frame latency, and
thermal impact must be measured on the device. Earlier alpha.59 thermal evidence
is historical and is not a thermal pass for this candidate.

Clean debug and release unit suites: 534 tests each, zero failures/errors/skips.
Release APK assembly, lint (zero errors), manifest and embedded-privacy audits
passed. The delivery build is repeated after documentation is committed so the
archive and APK manifest identify the complete source revision.
