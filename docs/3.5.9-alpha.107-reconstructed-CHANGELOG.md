# Alpha.107 reconstructed local — native app placement during Duo handoff

VersionCode 1360. Based on alpha.106 source commit
b940b2c812b627611333ce70a978b7f1391e10e7.

## Evidence and comparison

Both supplied failures are fatal exceptions in system_server's android.display
thread, through DeferredDisplayUpdater.applyLatestDisplayInfo,
DisplayContent.reconfigureDisplayLocked, TransitionController.setDisplaySyncMethod
and BLASTSyncEngine.setSyncMethod. The exception is “Not allow to change sync
method after adding group member.” The Instagram closing incident (session
19589127, sync group 475) fails at wallMs 1794183420076, 234 ms after the logged
primary request. The Plex landscape opening incident (session 22233980, group
117) fails at wallMs 1794186064858, 141 ms after the primary request. The subsequent
DeadObjectException at isKeyguardLocked is a consequence of system_server death.
Brightness preparation completed in both sessions. These records establish the
platform failure, but do not expose every Samsung transition participant or
prove the exact vendor-internal race.

The alpha.106 code has an important routing difference:

| Behavior | Live Screen (CoverHandoff) | Duo direct route in alpha.106 |
| --- | --- | --- |
| Primary panel change | Device-state request | Device-state request |
| App placement | Android keeps app on logical D0 | Explicit D0-to-D1 root move before primary request |
| Readiness/cleanup | No app task routing in CoverHandoff | Can move root back to D0 and write task focus |
| Content | Live rendering/mirrors | Independent screenshot buffers |
| Brightness | Native policy | Bounded reassertion of measured positive physical brightness |

Duo's brightness writer does not intercept or reject Android's zero command.
It submits measured positive per-panel values through SurfaceControl; API
acceptance does not prove uninterrupted visible brightness. No brightness,
power-state, renderer, capture exclusion, rotation, or Live Screen implementation
is changed in this release.

The task move and the subsequent physical display remap create separate WM work.
The direct route no longer uses the intermediate D1 app for capture: it already
captures the destination only after its new D0 mapping and layout are verified.
That makes the pre-remap task move unnecessary for the current screenshot path.

Android reference for the invariant (not Samsung firmware source):
https://android.googlesource.com/platform/frameworks/base/+/master/services/core/java/com/android/server/wm/BLASTSyncEngine.java

## Change

Direct Duo selects the existing primary app in observation-only mode and leaves
it on logical D0 through the physical panel exchange, matching Live Screen's
app-placement model. It skips the legacy task-move phase entirely. Native app
readiness cannot move a root, force focus, restore a root, or force endpoint
relayout. An unexpected placement/layout remains unverified and uses the bounded
existing recovery/observation policy. The native guard is enabled before selection
so even a partly failed selection cannot authorize a cleanup move.

Immediately before primary switching, read-only source checks confirm the selected
root is still the visible focused D0 app on the expected physical panel. Outgoing
coverage, producer drain, brightness validation, physical rotation pair, current
motion, cancellation and endpoint gates remain in force. After remap, the existing
destination geometry, native readiness and exact destination capture checks still
run. Brightness protection, moving screenshot animation, 1.5-second pause rule,
280 ms unwind and 160 ms dissolve are retained. Home/workspace behavior and the
non-direct legacy task route remain separate and unchanged.

Diagnostics identify this route as NATIVE_APP_PREPARED / NATIVE_PRIMARY_SELECT.
It must not emit TASK_MOVE_BEGIN or HINGE_MOVE for an ordinary direct Duo session.

## Validation and limits

tools/check_live_b8.py executes the real controller and task wrapper against fake
framework services. Added regressions cover both failure directions, pending
brightness, missing rotation proof, producer drain, stale remap geometry, missing
destination capture/native readiness, reversal, pause and cleanup. Real task API
checks cover portrait/landscape, a task unexpectedly on D1, a changed foreground,
lock and endpoint checks with zero move/focus/layout writes on the new route.
Existing brightness, source-stream, physical-scene and token-cleanup checks run.
tools/check_b8_baseline.py verifies the preserved Lab checkpoint. Delivery uses
tools/build_local_test.py for a clean committed build and all JVM unit tests.

No handset is connected. This removes the identified extra task-transition
sequence; it is not proof that every vendor display race or optical flash is
eliminated. On-device validation must include Instagram closing and Plex opening
in the same orientations, plus repeated reversals, partial-fold pause and normal
Home transitions. Do not label the firmware crash definitively cured until those
device runs succeed.
