
3.5.9-alpha.1 — stale hinge handoff fix + separate Fold Power Lab 0.2.0

Duo now retains an existing concurrent display request during a brief missing-angle episode. The absolute deadline is two seconds after the last valid sample; stale polls never renew it or request a new display state. Fresh endpoints, disable/lock, explicit shutdown and Android cancellation retain their existing cleanup behavior. Handoff reports include STALE_HOLD start/recovery/expiry. This targets the observed 69° stale-reading cancellation/reacquisition; hardware validation is still needed.

The second APK is Fold Power Lab, a separate package based on Fold Observer 0.1.4. It does not replace Observer or add experimental controls to Duo. It records 25 ms target software display/physical-identity/device-state/power samples with actual gaps, fold/Hall sensor callbacks where permitted, logcat, Perfetto and before/after system dumps. Full runtime API inventory is included; an exposed method is not proof of permission or effect.

Tests: read-only baseline; Samsung per-logical-display ON (D0, D1, both); bright-screen wake lock; concurrent inner/cover primary; concurrent primary combined with both-display ON. Each override is explicitly selected and bounded to ten seconds, with Stop, release reporting and shell-process termination if cleanup cannot complete. It never guesses untyped Binder transactions, changes persistent power settings, or automatically reasserts canceled requests.

Start with Power baseline, Duo disabled, and save the ZIP. Repeat with Duo enabled for observation only. Disable Duo before override tests; test one mode at a time using the same fold motion, foreground app and orientation. Wait for RECORDING in the notification. Save each report. D0/D1 can change physical identity during a handoff, so use uniqueId in the sample report. Accepted calls/commits do not prove visible pixels. Detailed tracing and sampling add overhead. This build has not been exercised on the phone.
