# 3.5.3-alpha.18 — short report primary and optional closing app return

Copy status report is now the primary filled button and excludes health history.
With health history is a smaller tertiary-colored text button. Both copy paths
explicitly select report contents; no health collection or history is removed.

Adds Closing app-first return (experimental), OFF by default in Developer settings.
For window-first screenshot sessions starting on the inner panel, it requests the
exact selected app back on D0 once at 0 < angle <= 15 degrees, while retaining
concurrency. Existing reports show Home focused on D0 while the app is on D1;
this tests whether an ordinary app on the primary display before native closure
avoids fold-triggered sleep. Causation and prevention are unverified.

This may interrupt live cover content near closure. Opening is unchanged. If the
fold reverses past 25 degrees after the attempt, or the option is switched off,
the test releases concurrency. Existing lock/stale/30-second cleanup stays active.
No wake/power APIs are added. APP-FIRST entries log the return and immediate focus
observation; ordinary endpoint power traces record whether sleep still occurs.
The 15-degree request can be missed on very fast closure; absence of a logged
attempt is not a successful test.

Keep screenshot handoff and window-first ON, both power experiments OFF. Compare
closing with the new option OFF then ON and copy status report after each group.
No global defaults change. Alpha.17 dimensions and rotation recovery remain.

Local whitespace and inner-stretch checks pass. CI runs eligibility regression
unit tests, full release tests/lint/build, existing signing and APK verification.
No handset or optical test was performed during development.
