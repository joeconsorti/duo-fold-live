## Changes and limits

1. Previously each logical SurfaceView changed its fixed raster between
   612x462 and 312x493 as it visited the two panels. That adds BufferQueue size
   changes and geometry invalidations to the primary-remap path. Each window
   now warms capacity for both observed panel extents and retains it for the
   scene. In the reported orientation/settings both use 612x493. Logical
   layout, physical identity, image selection and frame acknowledgement still
   follow the actual panel. The existing Canvas scale and SurfaceView scaling
   preserve logical aspect ratio; capture dimensions are unchanged. Capacity
   can grow for a resolution/rotation change but never shrinks mid-session.
   This removes avoidable buffer resizing; Android can still resize/recreate
   surfaces or delay layout and commits. It is not a proven optical fix.

   Tradeoff: two 612x493 rasters have 603,432 pixels, versus 436,512 for the
   previous two sizes: about 38% more raster area, or 667,680 additional RGBA
   bytes per pair of buffers. This is not actual GPU allocation (buffer count
   and driver allocations vary). Repeated allocation work is avoided, but
   sustained GPU/memory cost can increase. Full-resolution/AA settings still
   determine the divisor; no setting is rewritten. Capacity dies with the scene.
2. Shield arm now sets visibility and capture exclusion on containers AND
   buffer children in one transaction. Its commit supplies the previous hold
   evidence. The controller no longer submits a second identical show/exclusion
   transaction and waits another worker tick. It still requires ARM_COMMIT and
   both prepared app composites before requesting the primary exchange. The
   post-remap unmask and native-window readiness gates are unchanged.
3. Bounded recovery history records PANEL_MAPPING, PANEL_MAPPING_COMMIT,
   BUFFER_CAPACITY and new maximum MOVING_GAP events with session, logical
   window and physical identity. Diagnostic bufferChanges shows whether raster
   capacity was changed during a reversal sequence. mappingWaitMs starts at
   the latest observed mapping/state change, not the physical remap's onset.

No live mirrors, remap-time recaptures, Home selection, extra power hold, or
unconditional shield removal. Alpha46 frame pacing and coverage during
source-return cleanup remain. The freeze/flash causes are not optically proven.

## Validation

The deterministic harness passes 258 real-controller lifecycle/readiness
checks, bridge capture/arm/cleanup checks, and 25 brightness checks. The bridge
test now executes real arm() with fake capture/display APIs, verifies both
captures and local handle closure, verifies all layers are shown and excluded
in one transaction, rejects promotion before its delayed commit, and retains
the cleanup, stack-retargeting and handle-release checks. Controller tests
require both scene preparation and the shield commit, and assert promotion
occurs on the next eligible tick without a duplicate hold.
