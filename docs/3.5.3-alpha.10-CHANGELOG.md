# 3.5.3-alpha.10 — fixed-panel app routing experiment

Continues ci-118-1 on the alpha.4-derived lineage. Main remains unchanged.

Alpha.9's primary remap produced an observed blackout, including both displays reporting OFF. This diagnostic removes the second concurrent-state request entirely. After the outgoing screenshot commits, it activates the other panel while retaining the outgoing physical primary. Both panel identities, dimensions and ON states plus outgoing screenshot readiness must remain valid for 120 ms before requesting the selected app on logical display 1.

Only the exact focused fullscreen standard app selected before activation is routed. Home, Recents and multi-window are skipped. Task placement and focus are checked separately from panel readiness, at most ten times per second; neither establishes optical continuity or guarantees that app pixels have drawn. At release, only that routed task is returned to display 0 if it remains on display 1. Return is deferred while locked. Android can reject task routing; the request times out and releases the display override.

For this experiment screenshot mode renders one labelled frozen image on the outgoing panel and leaves the incoming app unobstructed. Glass animation and continuous glass capture are omitted in this mode to isolate the duplicate-image symptom. Other modes retain their rendering. The whole outgoing overlay root is excluded from the frozen capture. The 160-degree closing start with the default endpoint remains.

This is not a confirmed complete fix: Samsung Home/taskbar behavior is unresolved, and returning to normal mapping at the endpoint can still blank. No secure-content capture or lockscreen bypass is added.

## Device test
Keep animation enabled and both screenshot toggles ON. Start inside Duo on the cover. Unfold slowly to about 60–90 degrees, pause, and check whether the actual Duo app appears inside, can scroll, and has no ghost image. Note whether the outgoing cover stays lit with FROZEN COVER. Then finish opening and separately note any endpoint blackout. Repeat closing from inside Duo, pausing around 120 degrees before finishing. Copy the normal status report promptly; health history is unnecessary. This build intentionally has no glass animation in the tested mode.
