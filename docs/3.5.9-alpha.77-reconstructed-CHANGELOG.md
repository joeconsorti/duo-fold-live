# Alpha.77 reconstructed local — reject motion while physically closed

VersionCode 1330, based on alpha.76 (1d6d6643922d77c1d5c0ff8e10f4de254ac20558).
Recovery target remains alpha.20. This is a targeted correction for the reported
closed-phone restart loop; optical success has not been verified on a handset.

## Evidence from the alpha.76 report

The user confirms the phone stayed fully closed during the final approximately
ten seconds. Android's sampled base state remains 0:CLOSED from 429887070 through
429899403. Nevertheless, the wallpaper angle feed reports fresh 142-degree replies
at 429889815, 429892565 and 429895013. Each burst triggers a new Home presentation,
both-panel ON requests and an inner-primary remap, then returns to zero. These
three sessions begin at 429889825, 429892630 and 429895044. The overridden current
state changes to concurrent states 5 and 4 while the physical base remains CLOSED.

The prepared wake trace records fold-reason-13 recovery requests at 429887081,
429892023, 429894539 and 429896976. The later three recovery connections were
rearmed by the contradictory angle bursts. Display OFF/ON callbacks and screen
broadcasts corroborate the user's flashing report. Callback intervals are not
exact optical blackout times, and delayed broadcasts can arrive after wake.

AngleReader parses Samsung wallpaper mCurrentAngle responses and timestamps them
with log-message time. A newly logged reply can still contain an outdated angle.
The report does not reveal the original sensor event time or prove why Samsung
repeated exactly 142 degrees. The demonstrated application bug is admitting that
contradictory value as new physical motion and allowing another recovery episode.

Thermal status is 1 and sampled battery temperature is 33.5 C during the last three
sessions. Their app CPU samples are 22.80%, 29.30% and 26.86% of one core. Helper,
compositor and GPU cost are excluded. These samples do not establish the surface
hotspot temperature, a thermal peak, or a hardware fault. Older ChatGPT/camera
crashes in the shared buffer are not evidence of a current Duo crash.

## Changes

- Read physical base state on a bounded 100 ms target cadence and share that read
  between diagnostics and angle admission. Use base, never the app-overridden
  current state. This retains the existing Samsung state-0 CLOSED convention.
- Make CLOSED veto wallpaper motion before jitter filtering, animation, rotation
  and app-side motion/wake listeners. It applies even when optional jitter
  protection is disabled. Preserve raw wallpaper values in diagnostics.
- Keep the closed latch through unavailable or stale base reads. Before the first
  known state, unknown input cannot animate. After reopening, reject replies
  predating the last CLOSED observation; wait for a new reply without inventing
  a sensor timestamp. Normal opening may wait up to one base-poll interval.
- Recheck physical CLOSED independently at B8 session start/resume, before any
  capture/session, concurrent-state request or both-panel ON request. Wait for
  physical reopening without an abort/retry loop or new diagnostic folders.
- Allow at most one fold-recovery lease per observed physical open/close cycle.
  Angle jumps, screen broadcasts, unknown base reads and current-state overrides
  cannot rearm it. A genuine CLOSED-to-nonclosed base transition permits another
  lease. Base observations reach recovery independently of angle replies, so a
  real close during a sleeping/stalled angle feed is still recorded.
  Existing time bounds, fold sleep reason verification and keyguard policy
  remain in force. An already armed real-close lease may finish at CLOSED.
- Stop invalidating the keep-awake setting verification on every screen broadcast
  and every closing lease. Keep its existing periodic verification, actual setting
  observer, authorization/reconnect and explicit preference-change paths. The
  helper already skips identical setting writes; this removes redundant binds and
  reads rather than claiming that all previous transactions rewrote the setting.
- Report physical base, accepted angle and rejected-episode count. The LIVE angle
  shows the accepted value and flags wallpaper motion rejected while CLOSED.

No new unconditional wake request or permanent display-power setting is added.
The original mid-motion screen-off complaint remains separately subject to phone
verification. Package and signing identity allow installation over alpha.76.
The existing version migration resets Advanced animation controls; check and
restore any custom controls after installing. Other app data is retained.

## Validation and short handset check

Regression coverage replays four 142/0 bursts with base CLOSED and varying current
states: no session, task move, state request or ON request is permitted. Real
base TENT reopening admits early motion. Policy tests cover jitter disabled,
unknown/stale base reads, old replies across reopening, normal motion and wake
lease deduplication. Existing opening tests now explicitly model base TENT after
physical reopening; closing/cancellation fixtures retain base CLOSED.

Run the real controller/scene/task/power/brightness/cleanup harnesses and clean
build with the complete JVM suite, then lint. Package the committed source with
complete Git history, verify the APK identity/signature and archive hashes, and
save the APK and source before delivery. Exact completed checks accompany the
build report; host tests are not physical display or thermal measurements.

Let the phone cool with Duo disabled. After updating and checking Advanced
controls, use one normal open/close and leave it closed briefly. There must be no
new SOURCE_PREPARE/PREWARM or PRIMARY_REQUEST while base remains CLOSED. A raw
wallpaper 142-degree burst should show accepted zero and a rejection count, with
no new wake lease. Stop Duo if flashing or heating recurs. Report whether the
cover remains usable after the legitimate close and whether normal reopening is
responsive; do not extend a failing test to gather more evidence.
