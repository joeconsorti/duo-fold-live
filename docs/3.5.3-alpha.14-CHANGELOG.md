# Duo Fold Live 3.5.3-alpha.14

Based on alpha.13; main remains 3.5.2. No new power mutation in this build.

The user found a much shorter blackout with Dual-screen screenshot handoff OFF. In this configuration window-first startup and the Samsung ON-hold experiment do not run, even when their saved switches are ON. Treat this as a different route, not evidence that the ON override removed the blackout.

- Keep all saved options and existing handoff behavior. Show the active path and explain the inactive dependent switches in Developer settings.
- Include the dual/window-first/ON-hold configured and effective/eligible states at the top of both status reports. Mark historical screenshot text as inactive where appropriate.
- Observe panel identity, state and global interactivity during normal handoff as well as dual handoff. Motion trace runs for up to 30 seconds with a 3.5-second endpoint tail. Stale/disabled host stops the motion session; another trace requires an endpoint before rearming. Each motion is labelled with its route.
- After an observed primary physical remap, sample the exact fullscreen app's D0 WindowManager readiness for up to two seconds. Record dump start/end timestamps and first READY observation. This is sampled surface/window evidence, not a buffer-commit callback, optical timing, or proof of the first presented frame. A missing window, task selection failure, or delayed dump is reported rather than counted as ready.
- Retain four-finger developer shortcut and both copy buttons. No settings migration, automatic mode change, additional wake request, or forced refresh-rate change.

The proposed direct requestDisplayPower experiment was deferred before integration or delivery because the new user observation changes the baseline. Reference inspection found a direct device-state request path in AOSP main and an older Samsung decompilation; it remains untested on this handset. No direct requestDisplayPower call is included in alpha.14.

Validation: CI unit tests (including motion trace bounds and exact-task readiness matching), lint, assembly, signing and alignment. Phone testing remains necessary. Test first with Dual-screen screenshot handoff OFF and the other saved settings as reported, then copy the short report after a fold and unfold. Compare with dual ON separately if needed. Read-only sampling has overhead and may miss short state changes; trace timestamps are not blackout duration.
