# Alpha.79 reconstructed local — rotation release and blackout evidence

VersionCode 1332, based on alpha.78 b6d22ae7096c5118a13c7b0acb8bbbd91b6f1935.
Recovery target remains alpha.20. This is a test candidate, not a measured handset
speedup or a confirmed fix for Samsung's orientation decisions or optical flashes.

## Evidence and rotation changes

In the supplied alpha.78 report, the opening release begins at 442269658 with
both panels at rotation 0 and frozen=true. After PANEL_LOCKS/POSTURES they are
unlocked. By USER_ROTATION at 442269881 the inner is rotation 3, cover rotation 1.
On closing, release starts at 442283355; cover changes from 1 to 3, returns to 0
at 442287038 with the hinge still closed. frozen=false does not demonstrate a
working orientation sensor, a correct pose, or absence of fixed-to-user policy.
The actual sensor proposal/app policy was not recorded. These observations locate
a suspect release interval but do not establish the exact firmware cause.

- Experiment: restore fixed-to-user policy while the temporary panel locks still
  exist, before thawing. Previously auto-rotate was enabled while the app/sensor
  override remained active, then posture and user-rotation callbacks ran under it.
  AOSP DisplayRotation documents that fixed-to-user mode suppresses sensor/app
  selection even when the user lock bit is free. This sequence avoids that
  intermediate combination; Samsung behavior still needs device validation.
- When the destination posture is manually locked, restore the saved angle of
  that physical panel. Do not overwrite it with the outgoing panel's global
  user_rotation. Verify the manual angle as well as the lock and fixed policy.
  Auto-rotate restores the saved global value; no forced portrait or new lock is
  used to hide a wrong sensor decision. Every release phase is still attempted
  on failure; the durable journal, cross-process lease, recovery process and
  bounded retry remain. Original per-posture preferences use the existing vendor
  Binder API, never raw writes to the vendor posture map.
- Resolve the held physical panel again after slow journal preparation. Associate
  lock/user-rotation values with the panel snapshot, and reject a journal spanning
  a D0/D1 identity exchange before any mutation instead of saving mixed identities.
- Remove the unconditional second fixed-policy restoration and the wait before
  the first verification; keep two successful observations separated by >=100 ms.
  Failed verification still retries the fixed-policy restore. Skip a user_rotation
  write when the value is already equal, avoiding duplicate settings callbacks.
  Cache the journal only under the live owner lease; recovery reads disk anew.
  This removes repeated file reads from the 100 ms hold loop without weakening
  write-before-mutate durability.
- Status now says settings restored, with orientation response unverified. Record
  saved targets, actual per-panel user rotation, phase duration and physical IDs.
  A 10-second, 250 ms read-only change observer runs on the existing rotation
  worker after release. It stops when another hold starts and never re-locks.
  Rotation rows join fold-timeline.tsv at their original elapsed timestamps.

## Buffer performance and blackout checks

- Replace the shared serial blocking fence wait with zero-time fence polls on
  one scheduled worker. An unsignaled fence no longer blocks reuse of other
  signaled buffers on either panel. The existing 2-second limit retires the
  affected buffer; it never authorizes overwrite. Retired slots no longer count
  forever against the three-slot limit; a later draw can replace them. The last
  submitted content stays owned while waiting. No additional capture or power
  request is added. Readiness still requires a completed matching transaction.
- Report total/busy/retired buffer counts, allocation misses, fence timeout count,
  maximum observed fence wait, starvation onset and recovery. These can separate
  producer starvation from Android display power or native readiness delays.
- Log coverage-removal reason and stage, pending capture/readiness, ready-check
  age, angle age and main update gap before removing layers. Existing Home
  endpoint fail-open remains immediate; no new screenshot wait or power hold.
- Use the existing reader panel samples to record physical-panel OFF transitions,
  paired OFF observations and OFF-exit receipt spans (ON/DOZE distinguished). Logical remaps alone do
  not count as power changes. Unknown/duplicate identities break continuity;
  gaps are not blackouts. Totals include expected idle OFF states, and recorded
  spans are software observations, not optical duration bounds.
- With image diagnostics armed, analyze the already captured <=320px physical
  images for near-black opaque pixels and left/right counts. Whole-panel black
  requires >=98% near-black and >=99% opaque pixels; the intended black half
  alone cannot trigger it. Bright/dark/bright candidates require the same physical
  panel and geometry/rotation, short gaps and opaque bright bookends. Mark them
  as heuristics: dark apps, masks and omitted screenshot layers can explain them.
  No extra pixels/capture pass is requested. Counts and per-frame evidence appear
  in frames.json/review.html and the timeline. Missing captures remain gaps.
- Only while the image diagnostic is armed, request at most two post-release
  window-policy observations on a separate low-priority worker: after restoration
  and a subsequent tail rotation change. One job in flight, 1.5-second command
  wait, <=512 KiB accepted dump, <=32 filtered rows. Keep only numeric/enum policy
  fields (sensor proposal, app orientation, user rotation, fixed policy, pending
  rotation counters when firmware exposes them); no raw window titles or contents.
  A new hold cancels the observation. Missing fields/errors stay unavailable.
  This opt-in observation has overhead and does not gate rendering or cleanup.

The alpha.77 physical-CLOSED veto, bounded wake recovery, alpha.78 pause behavior,
Home alpha/readiness guards, secure capture checks, image budgets, bar method,
shader curves and thermal gates remain. No global polling frequency increase.

## Validation and phone test

Full JVM tests, compiled production buffer lifecycle harness, controller/cleanup/
brightness/scene/task/power harness, physical capture harness and lint are required
before delivery. New tests exercise release ordering despite phase failures,
locked-destination restoration, slow vs fast fences, timeout replacement, late
callbacks, identity swaps, unknown power samples, alpha/black-half rejection,
same-panel flash candidates, gap handling and bounded policy-field filtering.
The delivery manifest records the completed checks; these are host/fake-platform
checks, not Samsung handset or optical measurements.

Install the separate test APK over alpha.78. Existing per-version Advanced-control
migration still applies. Test Home and one ordinary app, auto-rotate enabled and
manual lock, portrait and landscape, both fold directions and a partial-fold
reversal/pause. In Flashing & system-bar diagnostics choose Arm next 6 folds,
reproduce once, leave the device in its final pose for ten seconds, then export
ZIP and copy the report. Describe the actual physical pose and whether turning
the whole phone responds while stuck. The unarmed normal report still includes
rotation, power and buffer metadata; detailed policy/image observations require
arming. Screen captures cannot establish emitted pixels or a hardware blackout.
