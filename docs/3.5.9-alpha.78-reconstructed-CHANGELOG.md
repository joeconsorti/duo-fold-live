# Alpha.78 reconstructed local — correlated diagnostics and pause completion

VersionCode 1331. Based on alpha.77 commit c395b071b2249a83bed4e24759202d6b79c9dc1f.
Recovery target remains alpha.20. This build adds observation and changes pause
rearming; it does not claim that flashing, native Home readiness, or system-bar
integration has been optically verified or fixed. Alpha.77's physical-CLOSED
veto and one-recovery-per-physical-cycle protections remain intact.

## Pause behavior

A continuous 1.5-second stationary observation (5-degree tolerance) finishes onto
the native panel: below 90 cover, above 90 inner, exactly 90 the active panel.
The existing 280 ms unwind and 160 ms dissolve/native readiness checks remain.
By default, further movement on the selected side does not restart animation.
Reaching the endpoint releases the pause; the next folding/unfolding leg can
animate. Before the endpoint, crossing strictly below 90 from a paused inner
panel, or above 90 from a paused cover panel, resumes at the current hinge pose.
Endpoint uses the existing configurable fully-open threshold (default 172) and
effective closed angle zero; it does not introduce a second endpoint threshold.

The Fine-tune toggle "Resume paused animation after angle movement" defaults OFF.
Turning it on restores the prior 5-degree rearm rule. The preference is outside
the existing per-version Advanced reset list and persists across upgrades.
Stale/invalid input or a transient power/keyguard eligibility gap cannot erase a
completed default pause. These gaps cannot count toward a new stationary hold.
Disabling the animation, changing route/resume mode, an endpoint, or crossing the
selected midpoint boundary clears/rearms according to the policy. The physical
CLOSED guard still rejects contradictory wallpaper input before this policy.

## Diagnostics

- A current-process, current-build bounded timeline retains 4096 events, maximum
  2400 characters of details each; the ordinary report includes its latest 240.
  It joins raw wallpaper/accepted angles and receipt age, base/current state,
  physical/logical panel mapping, display OFF/ON, screen broadcasts, session/task/
  Home/phase/revision/check identifiers, pause decisions, native readiness and
  imported shell handoff events. Original shell and app receipt times are distinct.
  No extra window dumps, capture, power request or wake lock is used by this
  default metadata recorder. Existing reader polling supplies 250 ms input and
  1-second app CPU/thermal samples. Passive battery events retain sensor timing;
  battery temperature is not surface temperature. App CPU excludes shell/GPU.
- Existing system-bar work is instrumented, without changing the selected method
  or capture/render gates. Record native readiness, optional-work gates, pacing/
  discovery/exclusion skips, queue/capture/delivery times, geometry and tile kinds/
  bounds, superseded results, composition queue/cost, first effect-texture use and
  renderer commits by bar revision. These distinguish missing native bars from
  capture/composition delays and stale output; commits are not pixel visibility.
- "Arm next 6 folds" now enables one shared Home/app/workspace image sequence on
  both physical panels in the Android 15+ direct path. It replaces parallel
  four-sample direct-app captures and the Home-only inner recorder. Full physical
  frames are <=320 pixels on the longest side. A single low-priority worker and
  no catch-up queue target eight total samples/second alternating panels, then
  two total samples/second for up to ten seconds after cleanup. New folds supersede
  the preceding tail. Motion/tail budgets are independent (240/20 attempts,
  12/3 MiB soft byte budgets with at most one bounded sample overshoot), 42-second
  total ceiling; the arm expires after ten minutes. At most 24 folders retained.
  Unarmed frames do not format/capture diagnostic image observations.
- OFF/noninteractive, locked, unstable or ambiguous mappings, and unavailable
  APIs leave labelled gaps. Moderate or higher thermal status suppresses image
  work. Capture skips if critical window work is already active; critical work
  never waits for this optional worker. Source frame references are dropped at
  cleanup; stop/rearm invalidates old work and clear prevents queued saves from
  recreating cleared evidence. Secure content remains rejected; skip-screenshot
  flags and renderer opacity are untouched. Diagnostic capture never wakes a panel.
- The ZIP includes fold-timeline.tsv and runtime-state.txt even without images.
  Fold folders contain frames.json, physical/source PNGs and review.html with
  playback and enlarged top/bottom crops of the same frame. These edge views add
  no capture workload. Missing samples are not black or passing frames. Images
  are sequential compositor evidence, not a camera video or proof of emitted
  pixels. Thermal suppression and busy gaps remain explicit.

Legacy non-direct comparison paths retain their existing four-sample behavior.
The old private Home-inner capture transaction remains compatible; the new
read-only transaction is separate and caller-UID protected by GlassCapture.
No status/taskbar visual redesign, new power hold, or wake-recovery loop is added.

## Validation and handset use

Policy tests cover 1.5 seconds, both panels/routes, exactly 90, same-side movement,
strict midpoint reversal, endpoint/next leg, optional 5-degree mode, dropped/
repeated/stale/future input, power eligibility and disable. The controller harness
feeds the real policy into the real controller for Home and ordinary apps in both
panel directions: settled layers removed, no restart/request on same-side motion,
new session after crossing, endpoint lease cleanup, next-leg eligibility.
Timeline tests check bounds, clock preservation, line sanitizing and report tails;
image budget tests reserve the closed-tail capacity independently of motion.
Run the full JVM suite, controller/cleanup/brightness/scene/task/power harness,
compiled bar-image oracle, physical diagnostic capture checks, and Android lint.
The delivery manifest records completed results; host checks are not phone proof.

After installing, check custom Advanced controls: the existing version migration
resets those controls. In Advanced/developer diagnostics, open "Flashing & system-bar
diagnostics", arm, test on Home or an app, and leave the device in its final pose
for ten seconds. Save ZIP to Downloads and attach it alongside the report. A test
that immediately flashes/heats should be stopped rather than prolonged. Check a
1.5-second pause at 120, continue to fully open, begin closing; also test reversing
from the pause below 90. Mirrored cover-side behavior should match. Actual bar
visibility, blackout duration and temperature hotspots still require handset
observation; an external camera is the optical reference if captures disagree.
