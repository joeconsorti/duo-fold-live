# Alpha.102 reconstructed local — bounded brightness reads and FPS attribution

VersionCode 1355. Based on alpha.101 commit 9d6edbf324211e33a44137184b42550f9ecc6eda.

## Current alpha.101 evidence

The new app-closing sessions 719151 and 737682 both abort because brightness
restoration observation times out. This is current-process evidence, separate
from the historical alpha.100/101 process reports.

- 719151: brightness failure at 721018, native fallback and unwind; native inner
  primary verified at 721131. Cover OFF observed at 721366, around 28 degrees,
  while full close is not reached until 722561. Cover comes back at the endpoint.
- 737682: brightness failure at 739708, 2026 ms after session start, around
  19 degrees. Recovery returns to the native inner primary. Cover OFF observed
  at 740054, around 11 degrees; cleanup completes at 740268, still around
  8 degrees. Full close occurs at 741003, cover ON is observed at 741130,
  and physical identity is confirmed at 741148.

The controller cancels its concurrent-panel request in nativeFallback. Android
then keeps the native inner primary and powers the cover down until closure.
This matches the reported pre-close black screen. The roughly one-second
cover OFF span is software sampling evidence, not an optical measurement.
There is no current closing sleep event tying this incident to the pending
keep-awake helper connection. Its warning is a separate unresolved condition.

## Change

Brightness observation previously launched a full 30,000-record logcat tail
for every retry, although each post-clear read had only 400 ms to finish. The
report confirms these reads timed out; it does not measure how much of that
latency was child startup versus dumping history. Replace the large dump with
a finite 512-record recent tail (98.3% fewer requested records). Missing samples
still use the existing one-time temporary refresh, only after both panels are
ready. Restoration must still be a positive SDR command for the correct
physical display, timestamped after that panel's temporary override was cleared.

The source owns and terminates its active child on cleanup. A timed-out,
failed, or oversized snapshot is never parsed as successful output. Each retry
unlinks the previous snapshot inode so a late child write cannot contaminate
its replacement. Per-read duration and failure diagnostics identify the short
source path in the next diagnostic ZIP. No larger timeout, guessed brightness,
additional power hold, or change to native fallback release was introduced.
If the new bounded read still fails, the conservative recovery remains; this
build has not been observed on the handset.

The alpha.101 completed-frame 280 ms unwind and subsequent 160 ms dissolve,
1.5-second hinge-pause behavior, and existing rendering/frame cap are preserved.

## FPS comparison from the supplied report

| Latest retained sample | Cover | Inner |
| --- | ---: | ---: |
| Live Screen submitted FPS | 96.9 | 100.4 |
| Duo closing session 737682 submitted FPS | 57.5 | 57.8 |
| Duo 737682 presentation-callback FPS | 58.2 | 58.4 |

The latest Duo close has 18–19 ms maximum moving submission gaps while its
cover is subsequently powered off. The blackout is not explained by a low
steady rendering rate. Other retained Duo folds show about 51–55 submitted FPS
and gaps during remapping/recovery. Duo is still paced near 60 submitted FPS;
this release does not raise that cap.

The Live values are short rolling painter/submission samples, whereas Duo's
values are whole-session buffer rates. Alpha.101's generic renderer counters
can mix embedded and secondary painters and have no mode/time label. The last
recorded animated cycles before the mode switch are Live, which supports that
attribution, but the numbers are not a controlled, equally windowed benchmark
or measured optical/panel FPS. The late cycles use 50% effective resolution per
dimension at thermal status 0 despite a 100% selection. Earlier 25%/thermal-2
Home sessions and historical processes are not pooled into this comparison.

For subsequent tests, the generic rolling counters now accept only active
Live primary SurfaceView submissions. Embedded Duo paints, frozen/reflected
secondary painters, screenshot routes and idle clears are excluded. Counters
are isolated by renderer identity and panel, include sample age and window
length, and count rollover intervals correctly. Duo retains its independent
per-session submitted/presentation-callback metrics.

## Validation

The JVM suite passes 741 tests with no failures, errors or skips. The real
controller harness passes 1128 checks; existing brightness (81), new log-source
(17), scene (28), task (70), power (19), and bridge cleanup checks pass. The
committed delivery build reruns the full JVM suite. Added tests cover large retained log history, latest OFF veto,
timeouts, nonzero exits, byte bounds, cancellation during a read, late child
writes into an old inode, and an actual finite child process. FPS tests cover
consecutive windows, renderer replacement, per-panel separation and long gaps.
Existing brightness freshness/cleanup and controller tests remain required.
No connected SM-F971U is available; the next app-closing test must establish
whether this change eliminates the visible blackout.
