# alpha.33 reconstructed — retain native-panel snapshots through remap

Version 1286. Reconstructed source; original-source equivalence is not claimed.

## Evidence and change

The alpha.32 composition ZIP showed wallpaper already baked into the source
image captured during the primary refresh, on both cover (sample 242927353,
source stamp 242927018) and inner (sample 242936045, source stamp 242935681).
The source, rendered buffer and captured composition matched while the later
underlay samples showed the app without the mixture. Earlier destination
captures showed the app without that mixture. This identifies the replacement
snapshot as a carrier, but does not establish which layer or firmware transition
produced the mixture. Sequential samples are not optical or causal layer proof.

Coordinated Screenshot Test now retains the native destination image captured
before the independent shield/remap. It no longer replaces that image with a
post-remap display capture, including during endpoint release and cancellation.
Snapshot mode also no longer uses the generic primary live-capture fallback.
Initial source capture and pre-shield destination capture/recapture remain.

After remap, native selected-task HAS_DRAWN/readiness is still checked. A retained
image must match physical identity, logical width/height and rotation before
readiness can be acknowledged. A matching committed primary presentation is
still required. Missing or mismatched images do not trigger an unsafe recapture
or a readiness pass; existing controller timeout/cleanup bounds apply.

This is a targeted avoidance of the observed capture interval, not a claim that
all display captures are now app-only. The held content is intentionally static
until native reveal. A rotation/geometry change during a fold can take the
bounded cleanup path. Live-mode captures are unchanged. Both screenshot
animations remain OFF; power policy, shield implementation and fade settings
are unchanged. Composition image diagnostics remain available.

## Verification and handset test

Unit coverage checks both physical panels, rotated dimensions, wrong-panel
images and missing/invalid metadata. Run the complete unit/build pipeline and
the existing real-controller/bridge cleanup/brightness harness before delivery.
No handset is attached to the build environment; visual success remains untested.

Install over alpha.32. Keep Coordinated Screenshot Test and custom wallpaper
enabled. Open and close slowly, then at normal speed. Inspect both near-endpoint
panels. Share composition images and the connection report. Expect
PRIMARY_SNAPSHOT_RETAINED with the earlier source stamp instead of
PRIMARY_SNAPSHOT_REFRESH. A matching diagnostic alone is not visual success;
inspect the actual source images for contamination.
