# 3.5.3-alpha.20 — closed-hinge jitter protection

The stationary-phone alpha.19 trace repeatedly starts normal cover previews at 3°, including one session lasting 26.5 seconds. The old 2° closed threshold lets these small readings start and hold a preview.

Add Closed-hinge jitter protection at the top of Developer settings, enabled by default when no preference is saved. OFF persists and restores the old angle threshold behavior. With the default closed threshold, start at 4° and reset at 2°; after starting, pass actual hinge angles through. For a custom closed threshold, the start is 2° higher. There is no time delay or Samsung folded-state gate in this first test.

The helper filters the angle once, before display requests, cover preview, rotation/fade decisions, and the angle returned to the app renderer. This prevents suppressed 3° readings from silently activating the second panel. Raw readings remain visible; the short report includes the effective angle, latch state, thresholds, and suppressed excursion count.

Tests cover sustained 3° readings, boundary chatter, immediate opening at 4°, closing through 3° to 2°, toggling, custom thresholds, stale/invalid readings, and helper restarts. CI runs unit tests, lint, APK assembly, and signature verification. Device validation remains necessary: noise reaching 4° can still pass this simple gate.

Test: leave the unlocked phone fully closed for a few minutes, then open slowly and normally. Compare ON/OFF using Developer settings and copy the short report if the false start returns or onset feels too late.
