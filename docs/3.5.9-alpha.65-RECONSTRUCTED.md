# Alpha.65 reconstructed — Duo workspace visibility

Version code 1318. Private candidate based on alpha.64, recovery target alpha.20.
No original-source equivalence or handset verification is claimed.

The reported alpha.64 export `Duo-composition-1793303753770.zip` contains only
capture-status.txt and README.txt. It explicitly records zero current-build image
folders despite six armed workspace sessions. There are no pixels to inspect.
The code disabled moving diagnostics for workspaces. The accompanying log records
successful two-task handoffs and one brightness preparation timeout; successful
readiness and cleanup cannot establish what either panel actually displayed.

Two concrete composition defects were found: workspace snapshots excluded all
injected photo leaves, and the cross-panel painter clipped an inner snapshot to
a contained horizontal band while its cover shader used a fill projection.
The ordinary display snapshot could also retain Samsung transition/dim layers;
this is a plausible explanation for faint panes, not a confirmed pixel diagnosis.

With custom wallpaper enabled, workspace capture now uses isolated screenshots of
every selected application window. UiAutomation resolves exact task IDs and stable
native bounds, including two tasks from the same package; the existing enabled
accessibility service performs the public window screenshot operation. The saved
panel wallpaper is composed once beneath these windows in layer order. Original
pixel alpha is preserved; no brightness/opacity boost or dark-pixel replacement.
Physical mapping, rotation, complete membership, activity/user identity, geometry,
and all-pane HAS_DRAWN are guarded before and after. Mismatched buffer dimensions,
missing/secure panes, ambiguous windows, remaps and timeouts reject the whole image.
All pane requests share an 800 ms callback deadline; existing per-window pacing
applies. Late callbacks close their buffers; partial groups are never published.

With custom wallpaper disabled, the guarded native display capture remains and
keeps its wallpaper. Isolated workspace capture currently uses the existing photo
host window registry; no service permissions or new automation connection are added.
When that enabled host is unavailable, the isolated path reports rejection and
uses existing native recovery instead of silently substituting a dim display image.
Dialogs/additional windows for one task are conservatively rejected because a
parent screenshot may already contain its child; never blend that subtree twice.

Both Duo buffer backends use the same native-managed projection for backdrop,
clip, and glass. Inner-to-cover fills the cover; cover-to-inner retains all source
content at panel height until the native destination workspace capture arrives.
Legacy Live Screen, single-app and Home behavior and all saved controls stay as-is.
No hinge, gyro, pause, rotation, brightness hold or endpoint policy changes.

Workspace moving diagnostics are enabled. They save the retained source image and
physical compositor samples with workspace provenance, without applying the old
exclusive-single-task observation. Failures remain inconclusive; source images can
still be saved when a compositor sample fails. Images are only collected when armed.

Validation: Android debug/release build and unit checks; production WorkspaceFrames
test with fake framework callbacks covers two/three panes, ordering, pre/post guards,
geometry mismatch, secure/missing pane, timeout/late callback cleanup and real dark
sample delivery. Existing Home capture, B8 lifecycle/task/power/brightness/scene,
buffer ownership and shader checks remain required. Fake pixels do not verify Samsung
visual appearance. Re-test opening/closing with two/three panes, including pause and
reversal; arm composition images before the folds and export afterward.
