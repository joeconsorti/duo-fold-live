# 3.5.3-alpha.7

## Developer preview: live blackout-free handoff

- Adds **Blackout-free handoff · DEV PREVIEW** under Advanced → Developer settings. It is OFF by default and does not change stable/default behavior.
- The preview runs inside the normal Windowed Glass fold and unfold animation. There is no separate test activity to arm for normal testing.
- While the developer preview is enabled, Duo pre-attaches a transparent, non-touchable window to the destination built-in display before hinge movement. As movement begins, Duo keeps the currently active physical panel primary while requesting Samsung's matching concurrent state so the destination panel is already ON.
- The existing live secondary preview bridges the transition while the outgoing panel remains primary.
- At the configured handoff angle, Duo requests the currently focused native Home/app task on the already-live destination display. Task placement, rather than global-focus ownership, is the handoff gate.
- Once native destination placement is observed, Duo removes the secondary mirror, requests destination focus best-effort, waits a short bounded settle, then releases the outgoing concurrent hold so Samsung can complete its normal physical-panel change.
- The old black handoff mask and bright expansion bridge are disabled only while this developer preview is enabled, so a real panel blackout remains visible during testing instead of being hidden by Duo.
- The same flow is attempted in reverse while folding: hold the inner-primary concurrent state, wake the cover as the second panel, use a bidirectional compositor mirror for the inner → cover bridge, place the active task on the cover, reveal it, then release the inner hold.
- If Samsung cancels the concurrent hold or task placement fails, the preview exits cleanly and returns control to normal mapping.
- Dual-screen screenshot handoff and the older timed continuity probe cannot run simultaneously with this preview.
- Copy status report now records whether the preview is enabled and its current handoff phase.

## Release workflow

- Development pushes now run tests/lint/unsigned build validation without publishing GitHub releases.
- Signing and GitHub publication occur only for the final release-marker commit (or an explicit manual workflow dispatch), preventing multiple releases for one alpha build.

- Release candidate assembled from the validated developer-preview branch; normal/default behavior remains unchanged unless the developer toggle is enabled.

- Final live preview includes the window-first destination prewarm and bidirectional cover ↔ inner compositor bridge.
