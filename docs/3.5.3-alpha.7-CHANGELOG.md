# 3.5.3-alpha.7 — outgoing screenshot / incoming live diagnostic

Continues new alpha.6 (ci-115-1), not the discarded earlier alpha.7 branch.

## Corrected meaning of screenshot mode
On unfolding: cover = its own frozen image plus animation; inner = uncovered live content. Folding reverses outgoing/incoming roles. Alpha.6 erroneously put the outgoing image on both displays. This diagnostic removes all imagery and glass from the incoming activation window so Samsung's content can be inspected directly. Incoming glass is deliberately deferred until its correct live content source is established.

The outgoing overlay now includes a full screenshot beneath its animation, and accepts the snapshot only for its source panel. Concurrency waits for that exact screenshot's frame-commit callback and the attached incoming window. Then it immediately requests the matching concurrent state while retaining the outgoing physical primary. No added timer or handoff-angle delay precedes activation.

The incoming anchor stays attached, transparent and touch-through, with window alpha zero as in the alpha.5 underlay reveal. No task movement or native-layout repair is included. Stretched launcher / App disabled may remain and should be reported.

## Diagnostics
- Outgoing screenshot stamp, source and frame-commit age in lifecycle log.
- Per-display physical ID, power state and logical dimensions at request and on state changes (sampled at up to 10 Hz).
- Incoming root tasks/configuration once the secondary panel reports ON.
- Explicit endpoint, cancellation, stale-angle, lock/disable, error and timeout release reasons.
- Normal display report includes Samsung BUILTIN enumeration; zero draws for an invisible anchor is not a failed activation signal.

Software ON/commit observations are not optical proof. Final endpoint remap may still black out. Native inner layout remains unresolved.
