# 3.0.4-alpha.7 — automatic one-time rotation repair

- Existing installations automatically perform the verified alpha.6 auto-rotate repair after updating, while the device is awake and unlocked and Shizuku is connected/authorized. Fresh installations skip this legacy repair.
- Pause the angle reader and overlays before repair without changing the saved Enable fold animation preference. Resume according to the current preference after successful completion; user changes made during repair are preserved.
- Save completion durably in app preferences and an installation-specific shell marker. Later updates, process restarts, and lost helper replies do not repeat a completed migration. Failures remain pending and use bounded retry backoff; no wake locks or unbounded task queues added.
- The migration explicitly enables auto-rotate for both postures once. Users can subsequently turn it off in Samsung settings; completed migration will not turn it back on.
- Keep Advanced settings > Repair auto-rotate available for explicit future repairs.
- GitHub releases from main and other branches remain pre-releases. CI requires an alpha version suffix until the owner approves changing that policy.

The existing package-replaced/boot receiver starts the background supervisor. Android may defer background startup; the migration then resumes at the next permitted service start. Shizuku authorization is still required. Status reports include migration waiting/retry/completion status. No animation geometry, handoff timing, or rotation hold/release changes from alpha.6.

Validation: migration-policy and rotation regression tests run locally; full Android compilation, tests, lint and signing run in GitHub Actions. Upgrade lifecycle behavior requires phone verification.
