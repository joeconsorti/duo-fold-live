## Changes restricted to Home

* First native layout request starts after 20 degrees of travel (20 opening,
  152 closing with the saved 172 open threshold), once both presentations and
  brightness preparation are ready. Previously it waited until the saved 85
  degree handoff. Early promotion stays latched until crossing the saved handoff;
  subsequent reversals retain the existing 20-degree hysteresis. Home never moves
  a launcher root task. Ordinary app thresholds and readiness remain unchanged.
* Native-sized isolated launcher buffers can be accepted independently of
  animated accessibility screen bounds. The Android window screenshot captures
  the window surface subtree, whereas accessibility bounds describe its screen
  placement. Alpha55 required equality, which can reject a valid native buffer
  during transforms. Full native size, before/after physical display, rotation,
  task/window identity and launcher-content checks are still required. Inset
  buffers still require exact stable bounds. Old-panel and arbitrary-size buffers
  remain rejected. Alpha55 did not log actual rejected sizes, so this explanation
  is a candidate for some rejections, not proof that every rejection was spurious.
  New timing output includes buffer/window/display dimensions.
* At either endpoint, Home revokes its scene session and submits root removal
  before releasing native policy and cleaning resources. It does not wait for
  a capture, native readiness, blur dissolve, brightness, or presentation commit.
  Late capture delivery cannot reacquire the revoked scene. Ownership stays held
  until cleanup completes; no new session can race pending cleanup. This applies
  during preparation and Android cancellation as well as completed handoffs.
* Both Home destination placeholders now use a cached, tiny, strongly filtered
  texture through the same current-pose Windowed Glass/stretch painter as the
  native destination. Native arrival crossfades textures for 120 ms without
  resetting the hinge pose. The Home destination remains full-width throughout;
  the original app inner-half mask remains the default for ordinary apps.
  Cosmetic frames never enter heldPanels or native-capture acknowledgements.

The source renderer, shared shader programs, ordinary app capture path, task
routing, animation-start policy, power helper and rotation cleanup are unchanged.
The shared painter gains a default-false fullWidthHome option guarded by homeScene.

## Validation and limits

Production controller fake-platform suite: 486 lifecycle/readiness checks,
including earlier Home promotion, reversal latch, endpoint during missing capture,
early preparation, deferred cleanup, and unchanged ordinary app transitions.
Existing bridge cleanup, brightness (25), scene mapping (19) and task routing (24)
suites pass. Android unit tests and clean delivery build are run by
`tools/build_local_test.py`; packaging ties the APK and complete source to Git.

No handset is connected here. No claim of measured alpha56 latency, zero-time
preparation, perfect rendered pixels or optical verification. Native release may
expose Android's own transition; that is intentional when Home reaches the endpoint.
