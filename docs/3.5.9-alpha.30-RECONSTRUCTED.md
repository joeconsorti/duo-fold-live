# Alpha 30 reconstructed: selectable screenshot routes

Version 1283 / 3.5.9-alpha.30-reconstructed-local. Derived from alpha29.

## Evidence and change

The reported alpha29 unfold showed an OpenAI logo. The incoming decision accepted
1023/1024 dark samples on its first capture. HAS_DRAWN and correct physical mapping
cannot establish that app content has finished loading. Historical ChatGPT OOMs
and SurfaceFlinger layer-cycle crashes do not establish a crash during this episode.

Coordinated mode now retries near-black (>=1000/1024) captures within the existing
600–1200 ms bounded policy. Legitimately dark content remains allowed at the bound.
Visible matching-task Android starting/splash windows cannot satisfy capture or
readiness guards, regardless of their order in the window dump. Custom in-app logos
are not detected semantically. After each primary check, a guarded primary capture
refreshes the retained image; readiness also requires that exact replacement image
be committed. Shield containers and held buffer leaves are marked skip-screenshot
so the refresh cannot recapture its own shield. The primary capture budget starts when refresh begins. Stale session,
check, rotation and physical-mapping results are discarded. Existing controller
bounds still release coverage on failure; no indefinite splash masking is added.

## Two choices

The debug build exposes persistent radio buttons under Screenshot mode:
- Coordinated screenshots: existing B8 controller, independent buffer shields,
  alpha29 buffer retention, plus the readiness/capture changes above.
- Legacy screenshot · live incoming app: restores the existing window-first
  fixed-panel route. Commit outgoing screenshot and preattach the destination
  window, request concurrent panels, then move the selected task to D1 after stable
  panel readiness (120 ms). No 85-degree wait, incoming capture animation or endpoint
  black fade. The incoming overlay is explicitly transparent, including stale-frame
  cases. Native endpoint mapping and exact-task restoration remain bounded.

The legacy route reuses the newer commit-before-request, physical identity,
closed-hinge jitter, keep-awake and bounded endpoint-return protections. It does not
use B8 shields or live mirrors. Neither route can guarantee zero hardware blackout.
Switch only at a fully open/closed endpoint. The one-time alpha12 migration remains
one-time, so reopening the settings does not overwrite a selected legacy route.

## Validation

Host JUnit suite and fake-platform B8 lifecycle, brightness and resource-cleanup
checks. Delivery build recompiles and reruns JUnit. No handset/ADB available:
optical blackout, touch responsiveness, ChatGPT loading and thermal behavior need
SM-F971U testing. Try each mode with ChatGPT, both slow and fast folds/unfolds, and
include the selected mode and fresh handoff log if a logo or black screen persists.
