This supports an Android framework restart rather than a fresh kernel boot.
The reported reboot,lpm property is the last kernel boot reason; it is not a
new explanation for this incident. The historical ChatGPT OOMs are unrelated
evidence, not a diagnosis of this fold failure.

The report identifies the failing framework invariant and the handoff window;
it does not establish which operation caused the internal ordering violation,

No timing workaround or platform-crash fix is claimed in this build.

## Changes

- App-side fold, panel, input, capture/readiness, lifecycle and thermal/CPU
  metadata now goes to a bounded background journal in private files. Six
  process histories survive process/framework/device restarts. Each process
  retains two 512 KiB timeline segments, identity and bounded recovery text.
  Reports display the preceding two processes, separately labelled historical;
  ZIP export includes all retained processes. New startup rows cannot overwrite
  the previous process's journal.
- Writes batch every 250 ms; fsync targets one second. The producer queue is
  capped at 512 rows, overflow and write errors are visible, and partial final
  lines are not shown as completed observations. Abrupt failure or a delayed
  writer can lose the unsaved tail; persistence is not a guarantee of every
  last frame. Idle input/health disk sampling is reduced to 5/10 seconds.
- Recovery reads the latest 1200 crash-buffer lines with epoch timestamps,
  includes only the preceding five minutes, and saves that result. This removes
  the repeated large, unrelated historical crash payload from angle replies.
  Saved recovery is also exported when Shizuku is unavailable after restart.
- Shell journals record build, source package, pre-move and pre-primary-request
  markers, phase/task/target on abort, and exception stack. The first recovery
  snapshot is preserved in its preceding shell session and included in ZIPs.
  Shell ZIP retention orders journal file times across boots instead of comparing
  uptime-based folder numbers, which restart at zero on a full reboot.
- Copy status report works with persistent history even when accessibility has
  not reconnected. No text-diagnostic arming is required. Images remain optional.
- Alpha.95's animation gates, timing, renderer, capture and buffer ownership,
  thermal policy and poll cadence are retained. Compatible upgrades preserve
  saved controls. No continuous screenshots or logcat streaming are introduced.

## Validation and next reproduction

Host tests cover journal restart recovery, truncated append, Unicode/queue/file
bounds, retention, failed storage, ZIP export, and crash-window filtering. The
existing real-controller fake-platform handoff tests are also run. Delivery
uses tools/build_local_test.py on the committed tree, with unit tests, signature,
version and source-archive checks. No handset reproduction has been performed.

Install over alpha.95 and use the same controls. If it happens again, reopen
Duo Fold after recovery, copy status report, and save the diagnostic ZIP before
doing more folds. Text recording is automatic. Images are not required for the
system crash investigation; optional image capture adds work and may omit
protected surfaces. Software evidence does not prove physical panel pixels or
temperature improvement. Do not clear app storage or uninstall before export.
