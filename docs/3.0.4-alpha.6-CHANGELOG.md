# 3.0.4-alpha.6 — rotation release and recovery

- Snapshot both panels' fixed-rotation policies before applying a hold.
- Restore panel rotation locks by physical identity after display remapping; restore the destination posture's saved auto-rotate preference on the primary display.
- Attempt every cleanup phase even when another phase fails. Re-run thaw and posture restoration on retries instead of trusting a prior global-restored marker.
- Retain original policy snapshots until fixed-policy, frozen-state and posture-map readbacks pass twice. Keep cleanup retries alive after close while restoration remains pending.
- Advanced settings: Repair auto-rotate, available with fold animation disabled. This explicitly enables auto-rotate for both postures and restores default fixed-rotation policies, with connected Shizuku. It can recover from a prior hold whose recovery journal no longer contains the original policies. If a panel is absent, recovery stays pending; retry with that panel available.

Validation: changed Java rotation/recovery sources compile against Android 36; 25 focused rotation tests pass. Full Android build/lint/tests run in GitHub Actions. Device validation is still required.

Test first with animation OFF: Advanced settings > Repair auto-rotate; confirm rotation in both postures. Then enable animation and verify it locks during folding and releases after both endpoints, including repeated fast transitions. Copy the Rotation hold/release line if it fails.

A process crash or uninstall can interrupt cleanup of persistent system settings; the app cannot promise cleanup after it is removed. The repair action is explicit because an older damaged journal cannot distinguish a user's intentional lock from a leaked override. Animation rendering and handoff code are unchanged from alpha.5.
