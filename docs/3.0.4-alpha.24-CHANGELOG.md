**BROKEN: Do not use this build for normal operation.** Reported severe cover flickering, missing reflected left preview, and unresolved Keep Awake failures. Download retained for rollback and investigation.

## BROKEN BUILD — original notes


- The left inner preview now redraws the captured cover content and its cover animation, horizontally reflected, using the shared frame stream and existing glass renderer. The right compositor preview remains clean. The prepared full-left frost is removed during live preview.
- Keeps the center feather visible during the unfold preview and handoff; the short handoff hold uses a reflected clean cover snapshot before native inner glass takes over.
- Adds a screen wake hold on detected closing from an awake, unlocked session, with a five-second maximum and release shortly after fully closed, reversal, disable or service destruction. No wake-on-acquire flag is used.
- Rechecks the existing fold setting when closing starts. If sleep still occurs during that window, the authorized helper checks the system sleep reason and requests wake only for DEVICE_FOLD (13). Power-button, timeout, accessibility and unknown sleep reasons are left alone; keyguard is never dismissed. Missing vendor APIs are logged rather than guessed.
- Lifecycle diagnostics record hold activation and recovery outcomes. This is a stronger best-effort path, not a guarantee against Samsung firmware behavior; verify the first home-screen close after restart and power-button behavior on-device.

Validation: policy tests cover fold-only wake, expiration and invalid timestamps. Android CI covers compilation, unit tests, lint and assembly. Visual reflection/center-seam and Samsung wake behavior still require device testing.
