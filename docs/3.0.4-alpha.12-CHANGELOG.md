# 3.0.4-alpha.12 — Preserve photo ownership and renew Home attachment

The alpha.11 capture acknowledged attachment in 2 ms, but both Home surfaces were in the offscreen hierarchy during unlock. A new launcher drawing surface appeared while its accessibility window ID stayed unchanged. A callback was not evidence of persistent visible placement.

- Give the photo a verified, persistent wallpaper-area parent instead of creating an unparented root. Retain relative ordering against the negative-Z Home anchor. Reparent our photo when the organizer supplies a replacement area.
- Reattach the existing anchor on screen-on/user-present at 0/32/100/250/500 ms, and coalesce window creation/removal or window-state events. This handles launcher surface recreation without requiring a new accessibility window ID. Screen-off cancels queued wake work.
- Reuse the same surfaces; allow one reattachment request per entry at a time. Keep five-second timeouts and ignore callbacks for cancelled/replaced entries. No continuous reattachment polling.
- Report attachment acknowledgement separately from actual compositor visibility. Existing wallpaper renderers remain available; animation and rotation are unchanged.

Validation: Java compilation against Android 36 and attachment lifecycle/launcher-selection tests locally; full release tests, lint, assembly and signing in CI. Unlock/fold appearance still requires handset verification, especially the first frame of a recreated launcher surface. This is an experimental correction, not a guarantee that the flash is resolved.
