# Duo Fold Live 3.5.3-alpha.12

Endpoint sequencing experiment, based on alpha.11.

- On a completed unfold from cover-primary concurrency, cancel the concurrent request before returning the exact routed app. Wait until the incoming physical panel is logical D0 and ON, or up to 1.8 seconds, before returning the task. Disable/lock and cleanup still end the wait. Other release paths retain existing behavior.
- Add an independent endpoint power trace with a 25 ms polling target for 2.5 seconds after endpoint release or Android cancellation. Reports physical identities, dimensions, ON/OFF states, interactivity and last sleep reason. These are software observations, not optical measurements or guaranteed sampling intervals.
- Inspect the firmware's power/display Binder method signatures and include them in both copy reports. No speculative power methods are invoked.
- Retain alpha.11 startup, live app route, screenshot isolation and short report button.

Power investigation: fold_lock_behavior is already set to stay_awake_on_fold_key and a bounded screen wake lock already covers closing. AOSP requestDisplayPower describes OFF/reset-to-expected-state behavior, not a no-OFF transition veto. The saved Samsung firmware inspection describes OFF-gated physical remapping. This build does not claim to disable that gate or prevent closing sleep. A stronger control remains unverified.

References: https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/hardware/display/IDisplayManager.aidl and docs/FIRMWARE-DISPLAY-FINDINGS.md.

Validation: endpoint wait policy tests, existing release tests, lint, assembly, signature and alignment verification in CI. Device validation required for opening/closing blackouts.
